## 模块 A — 用户与权限

### A1 登录 / 登出
- **触发**:用户访问任意非 `/login` 路由。
- **输入**:用户名、密码。
- **规则**:命中 `users.is_active=1` 才能登录;失败仅返回"账号或密码错误",不区分。
- **输出**:写入 session,返回 `display_name`、`role`、`role_pages`、`role_actions`。
- **异常**:连续 5 次错误锁定 10 分钟(可选做)。

### A2 角色矩阵(对照 5.27 流程)

| 角色 | 工作台主功能 |
|---|---|
| 销售 | 报单、催款 T+7、减免申请、退车发起、提前退车/结清、报价单查看 |
| 财务 | 报单确认、厂家表上传与比对、首款流水回填、还款核销、减免复核、发票开具、返利录入、退车押金 |
| 运营 | 合同 PDF 上传、催款 T+3、本期还款上传、发票申请、过户登记、提前结清本金计算 |
| 车管 | 入库、出库、验车 |
| 老板 | 双指导价维护、价格特批、退车领导审批、全过程穿透、返利全量可见 |

### A3 操作审计
- **触发**:任何状态变更类接口被调用。
- **规则**:写 `audit_logs(action, target_type, target_id, detail, operator, ip_address)`。
- **不能跳过**的动作清单:报单创建/审批、计划比对、还款核销、减免、发票、退车节点、过户、出库、返利。

## 模块 B — 车辆资产管理

### B1 车辆入库
- **触发**:车管端"新增车辆"。
- **输入**:VIN(17 位,必填唯一)、车牌、车型、车厢、电池、是否新车、开票价、采购价、税率、月折旧期数、保险到期、年检到期、附件(发票/合同 PDF)。
- **规则**:
  1. VIN 长度=17,必须大写;重复返回"该 VIN 已入库"。
  2. `status` 初始化为 `在库`,`activated_at=NULL`(新车)或当前(二手)。
  3. 系统按"开票价 × 残值率"自动算 `estimated_residual_value`。
  4. 若车型在 `model_guidance_prices` 已维护双价,则不要求录入单车指导价。
- **输出**:车辆主数据 + 入库审计日志。
- **异常**:VIN 长度错;车型主数据缺失时仅警告,不阻塞。
- **界面要点**:车辆入库后即可在销售端"在库车辆下拉"中选择。

### B2 车辆状态机

```
在库 ──报单成功──> 报单锁定中 ──报单驳回──> 在库
报单锁定中 ──出库(租赁)──> 租赁中 ──退车验收──> 在库 / 二手车
报单锁定中 ──出库(以租代售)──> 以租代售 ──结清+过户──> 已售/已过户
                                  └ 提前结清+过户 ──> 已售/已过户
租赁中 / 以租代售 ──维修──> 待维修 ──修复──> 在库
```

### B3 车辆查询
- **角色**:全员可见列表(含老板穿透),不同角色看到的字段集不同(销售看不到采购价、税率、返利)。
- **筛选**:VIN、车牌、车型、状态、公司、车厢、是否新车。
- **导出**:Excel(老板/财务)。

## 模块 C — 指导价管理(双价 + 版本)

### C1 维护"租赁每期分期指导价"
- **触发**:老板端 `/admin/guidance-prices/lease`。
- **输入**:车型、租赁分期指导价(元/期)、备注、生效时间(默认即时)。
- **规则**:
  1. 写 `model_guidance_prices.lease_installment_price`,旧值入 `model_guidance_price_history(price_kind='lease_installment')`。
  2. **存量订单不变价**:已生成的报单/合同上的 `snapshot_*` 不回写。
  3. **新增报单按最新价**:任何"待价格特批驳回 → 重新报单"也按调整后最新价。
- **输出**:历史记录 + 影响车辆数(同车型在库数)。
- **异常**:价格 ≤ 0 不允许保存。
- **界面要点**:旁边显示该车型当前在库数、在租数。

### C2 维护"以租代售整车指导价"
- 与 C1 一致,字段=`sale_total_price`,`price_kind='sale_total'`。

### C3 指导价缺失预警
- **触发**:老板进入工作台。
- **规则**:列出所有 `状态∈{在库,报单锁定中}` 但车型对应指导价 ≤ 0 的车辆,提示老板维护。

## 模块 D — 销售报单(租赁 / 以租代售)

### D1 新建报单
- **触发**:销售端"新建销售报单"。
- **输入**:
  - 共同字段:VIN、客户、客户电话、收款公司、起租日、销售方式(租赁/以租代售)、销售顾问、备注、附赠物。
  - **租赁**:租期、月租金、押金、首期付款日。
  - **以租代售**:分期数、首付款、月租金、整车成交价。
- **规则**:
  1. 仅 `vehicles.status='在库'` 可报。
  2. 一辆车同时只能存在一个进行中的报单(状态 ∈ {草稿、待价格特批、待财务确认、已激活})。
  3. **报单创建即锁车**:`vehicles.status='报单锁定中'`,防止并发。
  4. **价格核对**:
     - 租赁:`rent < lease_installment_price` ⇒ 触发特批
     - 以租代售:`sale_total_price < sale_total_price_guidance` ⇒ 触发特批
  5. 写入 `sales_orders` 并保存双价快照 `snapshot_lease_installment_price`、`snapshot_sale_total_price`。
- **输出**:`order_status='待价格特批'` 或 `'待财务确认'`。
- **异常**:VIN 不存在 / 车不在库 / 已有进行中报单 / 指导价未维护时仍可报但不进特批。
- **界面要点**:右侧实时显示当前两条指导价及差额预警条。

### D2 报单驳回与重提
- **触发**:老板"驳回价格特批"或财务"驳回报单"。
- **规则**:
  - 报单状态置 `价格特批驳回` / `财务驳回`,**车辆状态恢复 `在库`**。
  - 销售可"复制"该报单到草稿,改价后重新提交。
- **输出**:审批流批次 `status='已驳回'`,审计日志记录原因。

### D3 报单查询
- **筛选**:状态、销售方式、销售顾问、客户、时间区间。
- **批量动作**:仅老板可批量驳回;财务可批量确认(同状态)。

## 模块 E — 价格特批

### E1 老板特批
- **触发**:报单 `order_status='待价格特批'`。
- **输入**:通过 / 驳回 + 备注(驳回必填)。
- **规则**:
  1. 命中 `approval_flows.ref_type='price_exception'`,只一步,角色=老板。
  2. 通过后报单转 `待财务确认`,**车辆继续锁定**。
  3. 驳回则报单终止,见 D2。
- **输出**:更新 `boss_price_approved_by/at`、`price_check_status='已通过'`。

### E2 财务确认报单
- **触发**:`order_status='待财务确认'`。
- **规则**:
  1. 必须先完成 F2(厂家表上传)与 F3(双表比对)且 `customer_plan_match_status='已通过'`。
  2. 通过后 `order_status='已激活'`,允许进入合同生成与还款计划落库。
- **异常**:比对失败时不允许激活,前端提示具体差异列表。

## 模块 F — 还款计划(双表生成与比对)

### F1 系统生成"客户还款计划表"
- **触发**:报单进入 `已激活` 后,系统自动写 `repayments`。
- **规则**:
  - **租赁**:第 1 期 `due_date = 起租日`(首期+押金已收),第 N 期 `due_date = 起租日 + N-1 月`(常用)。**5.27 文档"次月开始还款"仅以租代售适用**;租赁是否首期同月收取以合同为准。
  - **以租代售**:第 1 期 `due_date = 起租日 + 1 月`(次月起还);共 `loan_periods` 期。
  - 金额=`rent`(每期月租)。

### F2 财务上传"厂家还款计划表"
- **触发**:财务端"上传厂家计划表"按钮。
- **输入**:Excel(沿用现有模板,识别"应还款日期/客户应还金额合计")。
- **规则**:解析后写 `factory_repayments(period, due_date, amount)`,期数自增。
- **异常**:模板表头识别失败提示"未识别到厂家还款计划表头"。

### F3 系统比对
- **触发**:F2 完成后自动触发,或财务点"重新比对"。
- **比对维度**:
  1. 期数总数一致;
  2. 同期 `due_date` 一致;
  3. 同期 `amount` 差额=系统设定的"利差/管理费"区间(可配置);
- **输出**:`customer_plan_match_status ∈ {已通过, 差异待处理}` + 差异行明细。
- **界面要点**:差异行高亮显示,允许财务点"以厂家表为准重算"或"以系统表为准忽略"。

### F4 财务复核
- **触发**:F3 通过后,财务"复核两表"。
- **规则**:写 `customer_plan_match_status='已复核'`,触发 P 模块"单车盈利基础数据"生成。

## 模块 G — 合同与出库

### G1 线下签合同 + 上传 PDF
- **触发**:F4 完成后销售线下签字。
- **输入**:合同 PDF(必填)、合同编号、起止日。
- **规则**:写 `contracts` 主记录(沿用现 schema [database.py:155](../database.py:155)),`delivery_status='待出库'`。
- **输出**:`contract_status='执行中'`,`snapshot_guidance_price` / `snapshot_invoice_price` 锁定。

### G2 客户支付首款
- **触发**:客户线下打款。
- **运营**:登记 → `contract_initial_payments(payment_type='首付款'/'押金+首期', status='待审批')`。
  - **必填**:实付金额。
  - **选填**:客户付款截图。
- **财务**:对账 → `status='已审批'`。
  - **必填**:银行流水号、到账金额。
  - **选填**:公司收款截图。
- **规则**:租赁=押金+首期月租金;以租代售=首付款。

### G3 车辆出库
- **触发**:G2 财务审批通过后,车管端"出库"。
- **输入**:出库照片(必填,可多张)、出库单 PDF(可选)。
- **规则**:
  1. 校验合同 `down_payment_status='已收'` 且 `deposit_status='已收'`(租赁)。
  2. 写 `delivery_date / delivery_photo_path`,`delivery_status='已出库'`。
  3. 车辆状态:租赁=>`租赁中`;以租代售=>`以租代售`。
- **异常**:首款未到账时拒绝出库。

## 模块 H — 每日监控与催收

### H1 日终批处理(系统每日 00:30)
- **触发**:Cron 调度 `POST /api/jobs/daily-collect`。
- **处理顺序**:
  1. 拉取所有未结清 `repayments`(`status ∈ {待还款, 临近还款, 部分核销, 待催款, T+3运营已催, T+7销售已催, 逾期}`)。
  2. **T-3 预警**:`due_date - today = 3` ⇒ `status='临近还款'`,系统自动生成提醒文案并推送到运营工作台,运营可一键发送给客户。
     - **自动生成文案模板**(占位符由系统填充):
       ```
       尊敬的{客户姓名},您的车架号为{VIN}的车辆将于{应还日期}进行还款,
       本期应还金额 ¥{应还金额}(第{期数}/{总期数}期),
       请您按时将款项转入收款账户:{收款公司}-{银行}-{账号}。
       如已支付请忽略本提醒,感谢您的配合。
       ——{公司名称}
       ```
     - **运营线上通知动作**:
       - 工作台"今日 T-3 预警"列表展示每条待提醒记录(车牌、客户、应还日、金额、文案预览)。
       - 运营点【发送提醒】可选择渠道:① 短信 ② 微信(企微/客户群)③ 复制文案手动发送。
       - 文案允许编辑(保存后写回,但保留默认模板版本)。
       - 发送后写 `notification_logs(repayment_id, channel, content, sent_by, sent_at, status)`,在该期还款时间线上展示。
       - 同一期 T-3 节点可多次发送,但工作台只显示"未提醒"列表;已提醒的用绿色徽标标记。
  3. **T 日**:由 I 模块覆盖。
  4. **T+1 起**:每日写 `late_fee_ledger`(见 J 模块)。
  5. **T+3**:`status='待催款'→'T+3运营已催'`,生成运营催款任务 + 文案。
  6. **T+7**:`status='T+3运营已催'→'T+7销售已催'`,生成销售催款任务 + 文案;同时触发 H3 顺序扣款。
- **输出**:任务推送到对应工作台 + audit_logs。

### H2 催款执行
- **运营(T+3)**:打电话/上门后上传催款单截图 → `urge_records(urge_type='运营催款', urge_day=3)`。
- **销售(T+7)**:同上 → `urge_records(urge_type='销售催款', urge_day=7)`。
- **规则**:必须上传截图才能"标记已催"。

### H3 顺序扣款(T+7 仍未还)
- **优先级**(本次重定义,与 5.27 对齐):
  1. 保险/代办类(insurance_fee, service_fee)
  2. 维修/事故/罚金类(maintenance_fee, accident_fee, penalty_fee)
  3. 本期租金(rent)
  4. 滞纳金(late_fee,作为应收参与抵冲,优先级最低)
- **规则**:从可用资金池(押金或客户已多打的预收)按上述顺序抵冲;每笔写 `reconciliation_allocations`;滞纳金抵冲后同步更新 `late_fee_ledger.waived_amount`(仅在已审批减免时使用)和 `contract_fee_items(fee_type='late_fee').amount_paid`。
- **输出**:扣款明细、剩余欠款、滞纳金累计/已抵冲/已减免。
- **界面要点**:运营/财务能看到"扣款瀑布"可视化;老板视图可穿透到任意一笔。

### H4 锁车(T+7 后选择)
- **触发**:销售端"申请锁车"或系统达到锁车阈值(沿用现 [app.py:3637](../app.py:3637))。
- **规则**:不变,只补"催款记录已存在"的前置校验。

## 模块 I — 还款确认与计划表调整

### I1 运营登记本期还款
- **触发**:客户支付后,运营点【本期还款】。
- **输入**:
  - **必填**:期数、实收金额。
  - **选填**:客户付款截图。
- **规则**:写 `repayments.paid_amount`、`screenshot_path`(若有),状态置 `部分核销`(待财务核对)。

### I2 财务核销
- **触发**:I1 上传后,财务点【核销确认】。
- **输入**:
  - **必填**:银行流水号、实际到账金额。
  - **选填**:公司收款截图。
- **规则**(三分支):
  1. **等额**(`received == amount`):`status='已还款'`,计划表不变。
  2. **少还**(`received < amount`):
     - 当期 `paid_amount=received`,`status='部分核销'`。
     - 差额 `gap = amount - received` 累加到下一期 `repayments[period+1].amount += gap`。
     - 若已是末期则进入 H3 顺序扣款 / 退车结算。
  3. **多还**(`received > amount`):
     - 当期 `status='已还款'`。
     - 多余 `extra = received - amount`,**运营与客户确认抵扣月份**(前端弹框选择),系统按选择把后续 N 期 `status='预抵'`、`paid_amount=amount`。
     - 抵不完的余额记为 `客户预收(可选表)`,下次抵冲。
- **输出**:`bank_serial`、`verified_amount`、`waterfall_summary` 全量写入。
- **审计**:每次核销均写 `reconciliation_allocations`。

### I3 计划表展示
- **界面要点**:
  - 展示客户表 + 厂家表两栏对照;
  - 已"预抵"期数加灰色徽标;
  - 当期"差额顺延"用箭头连接后期。

## 模块 J — 滞纳金

### J1 计提规则(逾期即收,自动计提)
- **触发**:H1 日终批处理(`due_date < today` 且当期未结清)。
- **公式**:
  ```
  outstanding(t) = amount - paid_amount(t)
  daily_amount   = outstanding(t) × 0.0005   (万分之5/日)
  cumulative     = Σ daily_amount  (从首次逾期日起)
  ```
- **写入**:`late_fee_ledger(repayment_id, accrued_date, outstanding, daily_amount, cumulative_amount)`,`UNIQUE(repayment_id, accrued_date)` 防重。
- **同步落账**:每日批处理同时写/更新 `contract_fee_items(fee_type='late_fee')`,`amount_due = cumulative` 并同步状态,使其进入正式应收口径。

### J2 抵冲与收取
- **逾期 = 应收**:滞纳金一旦计提即为客户应付债务,需要收取。
- **抵冲优先级**:在 H3 顺序扣款中,`late_fee` 排在第 4 位(本期租金之后);客户主动还款时,如本期款项有富余且没有更高优先级未结项,则抵冲已计提滞纳金。
- **结清前提**:合同结清(自然/提前/退车)前,若 `late_fee_ledger` 存在未抵冲累计金额,必须走 J3 减免审批,否则视为应收,并入退车押金扣除或提前结清买断金额。

### J3 减免审批(销售发起 → 老板审批 → 财务执行)
- **触发**:销售端"滞纳金减免申请"(可在还款过程中、退车节点、提前结清节点发起)。
- **输入**:合同 ID、命中期数(可多选/全选)、减免金额或全额减免、原因、附件(可选)。
- **数据表**(沿用 K 模块结构,扩展 `waiver_kind` 区分租金/滞纳金):
  ```sql
  ALTER TABLE rent_waivers ADD COLUMN waiver_kind TEXT DEFAULT 'rent';  -- 'rent' | 'late_fee'
  ALTER TABLE rent_waivers ADD COLUMN target_period_list TEXT;          -- JSON: [1,2,3] 或 'all'
  ```
- **流程**:
  1. **销售发起** → `rent_waivers(waiver_kind='late_fee', status='待审批')`,推送老板待办。
  2. **老板审批** → 通过/驳回 + 备注;通过后 `status='已通过'`,推送财务待办。
  3. **财务执行**:
     - 在 `late_fee_ledger` 中按命中期数标 `waived=1`、`waived_amount=...`(新增字段)。
     - 同步 `contract_fee_items(fee_type='late_fee').amount_due -= waive_amount`。
     - 写 `reconciliation_allocations(allocation_type='late_fee_waiver', allocated_amount=waive_amount)`。
     - `rent_waivers.status='已生效'`,`finance_reviewed_by/at` 落库。
- **撤销规则**:仅"已通过未生效"可撤销;"已生效"需通过"反向减免登记"补登。
- **通知**:推送给销售、运营、客户对账页。

### J4 结算时机
- **退车节点(M 模块)**:
  - 若存在未减免/未抵冲的 `late_fee` 累计金额,M3 运营查数据时自动汇总到 `total_deduction`。
  - 销售如需减免,必须在 M1 之前或 M3 之前完成 J3 流程,得到老板批复后方可在退车单中体现。
  - **不再由销售在退车单上单点决定**,`return_inspections.waive_late_fee` 字段仅用于展示是否已经走完 J3。
- **以租代售结清/提前结清(N 模块)**:同上,需提前完成 J3 才能进入过户。

### J5 展示
- 合同详情页"滞纳金累计"卡片:本月新增 / 累计金额 / 起算日 / 已抵冲 / 已减免 / 待收。
- 老板穿透:可查任一车辆的滞纳金 ledger 与减免审批链路。

## 模块 K — 租金减免

### K1 销售发起申请
- **触发**:销售端"租金减免申请"。
- **输入**:合同、目标期数、减免金额、原因。
- **规则**:
  - 减免金额不得超过该期 `amount - paid_amount`。
  - 写 `rent_waivers(status='待审批')`。

### K2 老板审批
- **触发**:K1 提交后老板待办。
- **规则**:通过/驳回 + 备注;写 `boss_approved_by/at`,`status='已通过'/'已驳回'`。

### K3 财务复核 + 落库
- **触发**:K2 通过后财务待办。
- **规则**:
  1. 复核后 `status='已生效'`,`finance_reviewed_by/at`。
  2. 系统更新 `repayments[target_period].amount -= waive_amount`(下一期付款时直接体现)。
  3. 写 `reconciliation_allocations(allocation_type='waiver', allocated_amount=waive_amount)`。

### K4 通知
- 推送给销售、运营,客户对账时可看到减免说明。

### K5 撤销
- 仅"已通过未生效"可撤销;"已生效"不可撤销,需走"反向减免"补登。

## 模块 L — 发票申请

### L1 运营发起
- **触发**:运营端"申请发票"按钮(仅运营可见,合同首期/任一已收款期均可)。
- **输入**:收款公司名称、税号、抬头类型(企业/个人)、金额、对应期数。
- **规则**:写 `invoice_requests(status='待开票')`。

### L2 财务开票
- **触发**:财务待办"待开票"。
- **输入**:发票号(必填)、开票时间(必填)、发票 PDF/截图(选填)。
- **规则**:`status='已开票'`,写 `invoiced_at`、`processed_by`。

### L3 发票纠错(作废 → 重开)
- **场景**:发票号填错、抬头/税号填错、客户要求重开等。
- **触发**:财务在已开票记录上点"作废"按钮。
- **输入**:作废原因(必填)、作废凭证(选填)。
- **流程**:
  1. **作废**:财务点"作废" → `invoice_requests.status='已作废'`,记录 `voided_by/voided_at/void_reason`。系统保留原发票号、开票时间用于审计追溯,**不可删除**。
  2. **重新上传**:作废后系统自动派生一条同合同同期数的新记录(`status='待重开'`,`previous_invoice_id` 指向被作废的记录),进入财务待办。
  3. **重开提交**:财务在重开记录上重新填写发票号(必填)、开票时间(必填)、发票 PDF/截图(选填),提交后 `status='已开票'`。
- **数据模型扩展**:
  ```sql
  ALTER TABLE invoice_requests ADD COLUMN voided_by TEXT;
  ALTER TABLE invoice_requests ADD COLUMN voided_at TEXT;
  ALTER TABLE invoice_requests ADD COLUMN void_reason TEXT;
  ALTER TABLE invoice_requests ADD COLUMN previous_invoice_id INTEGER;  -- 指向被作废的记录
  ```
- **可作废的状态**:仅 `已开票` 可作废;`待开票`、`已作废` 不能再次作废。
- **审计**:作废、重开均写 `audit_logs`,操作人、时间、原因全量记录;客户对账页能看到完整版本链。

### L4 客户对账
- 合同详情"发票记录"卡片展示有效发票(`status='已开票'` 且未被作废)+ 历史版本链;运营可下载有效版本。

## 模块 L-附 — 对账与上传规则(全局)

> 所有涉及"对账 / 上传"的环节,统一遵循以下原则。**流水号/发票号是金额追溯的唯一锚点,因此必须填写;截图作为辅助凭证,选填**。

### 必填字段(所有对账场景统一)
| 场景 | 必填 | 选填 |
|---|---|---|
| 财务确认还款核销(I2) | 银行流水号、实际到账金额 | 公司收款截图 |
| 财务上传公司首款(G2) | 银行流水号、到账金额 | 公司收款截图 |
| 财务开票(L2) | 发票号、开票时间 | 发票 PDF/截图 |
| 提前结清/买断收款(N2) | 银行流水号、收款金额 | 收款截图 |
| 退车押金退款/扣减(M6) | 银行流水号(若有出款)、扣减金额明细 | 出款回单截图 |
| 运营登记客户付款(I1) | 客户付款金额、期数 | 客户付款截图 |
| 运营催款记录(H2 T+3) | 催款时间、沟通方式、结果备注 | 催款单截图 |
| 销售催款记录(H2 T+7) | 催款时间、沟通方式、结果备注 | 催款单截图 |

### 通用规则
- **流水号去重**:同一银行流水号不能重复登记到不同对账记录(防止重复入账)。
- **流水号长度**:不少于 6 位,允许字母数字混合,前后空格自动 trim。
- **发票号格式**:不少于 8 位,允许字母数字。
- **截图为选填**:不阻塞流程,但若上传则必须是图片或 PDF;系统留存附件路径供后续审计。
- **审计**:必填字段缺失时前端禁用提交按钮,后端兜底校验返回 400。

## 模块 M — 退车(到期 / 提前)

### M1 销售发起退车
- **触发**:销售端"发起退车"。
- **场景**:① 租期到期且末期已收;② 客户申请提前退车。
- **输入**:退车原因(到期退车/提前退车/租赁转购车/临时用车)、是否减免累计滞纳金(销售决策)、附件。
- **规则**:写 `return_inspections(sales_status='已登记', waive_late_fee=0/1)`,合同状态=`退车中`。

### M2 车管验车
- **触发**:车回库后车管端"验车"。
- **输入**:随车工具(三角架/反光衣/灭火器/楔块/千斤顶)、证件钥匙、公里数、车身/轮胎清洁、事故/违章/ETC/维修保养、出险加保费;若需维修勾选"待维修"。
- **规则**:`fleet_status='已填写'`,无问题 → 待运营查数据;有维修 → 车辆状态置 `待维修`。

### M3 运营查数据并填单
- **触发**:M2 完成后。
- **输入**:违章/ETC/事故等明细、应扣金额、押金抵扣项。
- **规则**:`operator_status='已填写'`,自动汇总 `total_deduction`、`actual_refund`。

### M4 财务复核押金
- **触发**:M3 完成后。
- **规则**:
  - 到期退车:扣减后 `actual_refund = deposit_paid - total_deduction(含滞纳金,若不减免)`,`status='待退款'`。
  - 提前退车:若约定有提前退车违约金,在 `total_deduction` 里加上;若押金不够则记应收账款。
  - `finance_status='已填写'` + `finance_approved=1`。

### M5 领导审批
- **触发**:M4 完成后,**领导审批 = 老板**(`approval_flows.ref_type='return_stock'`)。
- **规则**:通过=`boss_approved=1`,允许出款。

### M6 出款 + 入库
- **触发**:M5 通过。
- **规则**:财务出款打到客户账户,`paid_out=1`;车辆 `status='在库'`(若验车时为待维修则保持 `待维修`,修复后再回库)。
- **输出**:租赁流程结束,合同 `contract_status='已退车'`。

## 模块 N — 过户(以租代售结清 / 提前结清)

### N1 自然结清
- **触发**:I 模块某一期核销后,系统检测 `Σ paid_amount ≥ Σ amount` 且 `period == loan_periods`。
- **规则**:
  1. 财务复核结清,销售决定滞纳金减免/收取(同 J3)。
  2. 创建 `ownership_transfers(status='待过户')`,推送运营。

### N2 提前结清买断
- **触发**:运营端"计算剩余应还本金"。
- **公式**:
  ```
  remaining_principal = Σ_{未还期} amount  -  减免  +  滞纳金(若收取)
  ```
- **流程**:
  1. 运营出报价 → 与客户确认。
  2. 客户一次性支付 → 运营上传截图 → 财务确认收款 → 写 `contracts.early_settlement_amount/early_settled_at`。
  3. 触发 N3 过户。

### N3 过户登记
- **触发**:N1 / N2 完成后。
- **输入**:过户日期、新车主名称、新车主身份证、过户材料附件(行驶证、登记证)。
- **规则**:
  - 写 `ownership_transfers(status='已过户', transfer_date)`。
  - 车辆 `status='已售/已过户'`,合同 `contract_status='已结清'` 或 `已提前结清`。
- **异常**:材料不全的过户单不能完结,可挂"待过户"长期跟踪。

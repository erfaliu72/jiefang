## 三类业务全链路结果

### 整车销售（16/16）
报单（无需指导价确认，直接待财务确认）→ 财务激活 → 上传合同 → 首付足额 → 财务审核 → 车管出库 → 车辆=已售、合同=已结清。全部断言通过。

### 经营租赁（含每期还款与退车，26/26）
报单（押金 10%、每期 1.67% 均达标，无需特批）→ 财务激活 → 合同 → 首付（押金+首期租金）足额 → 出库（车辆=租赁中）→ 每期对账核销 → 退车六步闭环 → 车辆回库。
要点验证：首次付款会自动核销押金（period 0）与首期租金，后续仅对未还款期逐期对账，符合系统设计。

### 以租代售（含价格特批、不足额出库、滞纳金、过户校验，28/28）
报单首付比例 10% 低于指导 20% → 老板价格特批通过 → 财务激活 → 合同 → 首付不足额（实收 60%）→ 财务审核触发不足额 → 老板同意不足额出库 → 出库（车辆=以租代售）→ 末期少还，日终批处理计提滞纳金 ¥46.5 → 销售发起减免、老板审批、财务执行减免成功 → 未结清时发起过户被正确拦截。

## 例外/分支验证

- 同 VIN 重复入库：被拦截（“车辆已在库”）。
- 价格低于指导口径：报单进入待价格特批，老板通过后转待财务确认。
- 价格特批驳回：报单作废，车辆释放回在库。
- 首次付款不足额：转老板审批，同意后差额挂账应收并允许出库。
- 未结清发起过户：被拦截（“客户分期尚未全部结清，不能发起过户”）。

## 测试过程中的认知修正（非系统缺陷）

1. 对账上传付款截图必须由「运营」角色发起（`/api/reconciliation/<id>/screenshot`），最初脚本误用财务角色，已修正。
2. 经营租赁首期租金随首次付款一并核销，逐期对账只针对未还款期；最初脚本要求全部期逐期对账，已修正断言。
3. 滞纳金减免需要存在已计提滞纳金，需用过去起租日构造逾期再少还，最初脚本用未来日期无滞纳金可减免，已通过提前起租日修正。

以上三点均为测试脚本预期与系统真实设计的对齐，系统行为本身正确。

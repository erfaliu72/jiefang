# 流程图（按最新规则调整版 v2）

> 本版沿用 5.27 原框架，在 20260803 版基础上按最新业务调整更新。
> 主要调整：
> 1. **取消整车销售环节**，仅保留**租赁**、**以租代售**两条主流业务流程；
> 2. **指导价格判断按业务模式区分**：
>    - **以租代售（以租代购）**：老板按车型设计 n 种金融方案（首付款、每期价格、期数三维度，可自由增删改），销售报单时从老板维护的方案中选择，**无"低于指导价"特批**；方案变更后，**已出库车辆按变更前方案执行，库中新车/二手车按新方案执行**；
>    - **租赁**：**押金与月供两者都不能低于老板指导价**，任一低于 → 老板价格特批；押金 = 老板端该车型押金指导价；月供 = 标箱/宽体/高栏/冷藏/平板（5选1）价格 + 尾板（加装 +300 / 不加 0）；价格变更后，**已出库车辆按变更前价格执行，库中新车/二手车按新价格执行**；
> 3. **车辆出库流程顺序调整**：
>    - 旧顺序：销售报单 → 系统判断是否低于指导价 → 系统生成报单 → 财务确认 → 运营上传合同 → 运营发起首次付款 → 首次付款判断 → 财务首付款对账 → 车管出库
>    - 新顺序：**销售报单过程即上传客户首次付款截图**（报单提交时一个动作完成：租赁 = 押金 + 第一月月供，以租代售 = 首付款，同时以租代售需选择还款方案）→ **系统判断首付款是否足额（按原流程）** → **首付款对账 + 财务报单确认** → **运营上传合同** → **车管出库** → 车辆状态：租赁中 / 以租代售
>    - 注：首次付款截图是**报单提交的一部分**，报单成功即完成首次付款上传，不存在报单成功后再单独发起首次付款的环节。

# 二、租赁流程

### 2.1 报单 → 首次付款 → 财务确认 → 合同 → 出库

```mermaid
flowchart TD
    A["销售端：销售报单 / 新建报单"] --> B["选择车辆：在库车辆"]
    B --> C["销售方式：租赁"]
    C --> D["填写租赁报单数据<br/>客户、起租日、租期、押金、月租金、收款信息"]
    D --> E["系统读取租赁指导价<br/>押金指导价 + 月供指导价"]
    E --> F{"押金 ≥ 指导押金<br/>且 月供 ≥ 指导月供？"}

    F -- "是：均不低于" --> G["报单成功<br/>（报单过程即上传客户首次付款截图<br/>首次付款 = 押金 + 第一月月供）<br/>车辆锁定（报单锁定中）"]
    F -- "否：任一低于" --> H["老板端：价格特批审批"]
    H --> I{"老板是否通过？"}
    I -- "驳回" --> J["报单终止 / 状态：已作废<br/>车辆回在库"]
    J --> A
    I -- "通过" --> G

    G --> M{"系统判断首次付款是否足额？"}

    M -- "足额" --> N["无需老板特批"]
    M -- "不足额" --> O["销售上报实收金额<br/>备注不足原因和承诺归还时间"]
    O --> P["不足部分挂账为应收<br/>承诺期内不记录万5滞纳金"]
    P --> Q["老板审批是否允许不足额出库"]
    Q -- "同意" --> R["差额保留为应收，允许出库"]
    Q -- "不同意" --> S["老板驳回"]
    S --> T["报单 / 合同终止<br/>车辆释放回在库"]
    T --> U["本单结束"]

    N --> V["财务端：首付款对账 + 财务确认报单"]
    R --> V
    V --> W["核对实际到账<br/>填写银行流水号（≥4位）或上传回单"]
    W --> X["报单状态：已激活"]
    X --> Y["运营端：上传线下合同 PDF"]
    Y --> Z["车管端：车辆出库<br/>上传出库照片 / 出库单"]
    Z --> AA["车辆状态：租赁中"]
```


# 四、每期还款、催收与计划表调整（租赁 / 以租代售共用）

说明：本章为租赁（第二章）和以租代售（第三章）在还款阶段共用的流程。系统每日自动执行，对所有未履约还款完成的车辆订单进行状态查询、催收和滞纳金累计记录。首次付款足额的判断已前移至报单环节（见 2.1 / 3.1），本章仅处理每期还款的少还 / 多还。

### 4.1 每日监控与逾期催收

```mermaid
flowchart TD
    A["系统自动执行（每日 00:30 + 启动补跑 + 查询兜底）"] --> B["遍历所有未履约还款完成的车辆订单和挂账应收"]
    B --> C["读取还款计划表 / 挂账应收<br/>检查应还日期、应还金额、实收金额、到账状态"]
    C --> D{"当前距还款日或承诺归还日的时间节点"}

    D -- "首次付款不足挂账<br/>仍在承诺期内" --> E0["只展示待归还应收<br/>承诺期内不记录万5滞纳金"]
    D -- "首次付款不足挂账<br/>超过承诺归还日仍未归还" --> E1["转为逾期应收<br/>按剩余欠款记录万5滞纳金"]

    D -- "T-3（还款日前3天）" --> E["系统自动黄色预警"]
    E --> F["生成提醒文案<br/>尊敬的xx，您的车架号为xx的车辆将于xx日进行还款，请您知悉"]
    F --> G["标记订单状态：临近还款"]

    D -- "T 日（还款日当天）" --> H{"客户是否已还款？"}
    H -- "是" --> PAY["进入还款确认与计划表调整流程（见 4.2）"]
    H -- "否" --> N["标记订单状态：还款日 / 待催款"]

    D -- "T+3（逾期3天）" --> O["系统自动生成运营催款文案"]
    O --> P["运营上传催款单截图"]
    P --> Q["标记订单状态：T+3 运营已催款<br/>保留催款记录"]
    Q --> Q1{"客户是否已还款？"}
    Q1 -- "是" --> PAY
    Q1 -- "否" --> Q2["继续等待至 T+7"]

    D -- "T+7（逾期7天）" --> R["系统自动生成销售催款文案"]
    R --> S["销售上传催款记录 / 催款单截图"]
    S --> T["标记订单状态：T+7 销售已催款"]
    T --> T1{"客户是否已还款？"}
    T1 -- "是" --> PAY
    T1 -- "否" --> U["进入顺序核销 / 风险处理记录"]
    U --> V["1. 保险 / 服务类费用"]
    V --> W["2. 维修 / 事故 / 罚金类费用"]
    W --> X["3. 本期租金及挂账应收"]
    X --> Y["4. 逾期滞纳金仅累计记录<br/>不自动收取"]
    Y --> Z["系统记录扣款明细、顺序、金额、时间、操作人"]
    Z --> Z1["逾期满 7 天可发起锁车申请（见 4.4）"]
```

### 4.2 还款确认与计划表调整

说明：当客户在任意时间点完成付款后（无论是否逾期），均进入本流程进行确认与计划表调整。多还款沿用原规则；少还款按本版新规则处理。

```mermaid
flowchart TD
    PA["销售/运营端：点击【本期还款】或【首期对账】<br/>上传客户支付截图并填写客户实付金额"] --> PB["财务端：核销确认<br/>填写银行流水号（≥4位）或上传回单"]
    PB --> PC{"比对实际付款与标准应付金额"}

    PC -- "按标准付款" --> PD1["正常核销本期账单<br/>还款计划表不变"]

    PC -- "多于标准付款" --> PD3["沿用原多还款规则<br/>运营与客户确认抵扣月份（必填）<br/>整期覆盖 → 已还款 / 部分覆盖 → 预抵"]

    PC -- "少于标准付款" --> PG1["实付金额记录为本期还款<br/>例：应还5000，实还4000，则4000记本期已收"]
    PG1 --> PG2["差额挂账为本期应收<br/>例：1000记录为应收"]
    PG2 --> PG3["差额按万5/日统计滞纳金<br/>滞纳金仅累计记录"]
    PG3 --> PG4["本车所有流程结束后<br/>由销售发起是否收取/减免滞纳金"]

    PD1 --> PE{"是否全部还清或租期到期？"}
    PD3 --> PE
    PG4 --> PE

    PE -- "否" --> PH["继续每日监控（回到 4.1）"]
    PE -- "是" --> PI["退出还款周期，回到主业务流程<br/>租赁→退车 / 以租代售→过户"]
```

### 4.3 租金减免 / 滞纳金收取确认流程

说明：在每期分期还款计划中可触发租金减免；本车流程结束时，由销售发起累计滞纳金是否收取或减免。

```mermaid
flowchart TD
    A["销售端：发起申请"] --> B{"申请类型"}
    B -- "租金减免" --> C["填写减免原因及金额"]
    B -- "滞纳金收取/减免确认" --> D["选择收取或减免<br/>填写累计滞纳金金额、原因和说明"]

    C --> E["老板端（领导）：审批"]
    D --> E
    E --> F{"是否通过？"}
    F -- "否" --> G["驳回申请"]
    F -- "是" --> H["财务端：执行减免"]
    H --> I{"执行结果"}
    I -- "租金减免" --> J["系统按命中期数更新还款计划表<br/>减免金额在对应期数中扣除"]
    I -- "滞纳金收取" --> K["生成滞纳金应收<br/>进入收款对账"]
    I -- "滞纳金减免" --> L["冲减累计滞纳金记录<br/>同步合同应收<br/>保留审批与减免日志"]
```

### 4.4 逾期锁车流程

说明：逾期满 7 天且该期已有催收记录后，销售方可发起锁车申请。

```mermaid
flowchart TD

    I --> J["客户还款后<br/>销售发起解锁申请（同样走运营审核 → 老板审批）"]
```

# 金聚源车辆管理系统 测试计划方案

- 版本：v1.0（2026-09-16）
- 适用对象：app.py（Flask 后端，148 个接口）+ templates/index.html（Vue 单页前端）+ database.py（SQLite，规划迁移 MySQL）
- 基线：8.25 诉求第二版已完成全量验证（见《20260916-8.25诉求第二版全量验证报告》），六条主流程冒烟 58/58 通过，自动化回归 70 用例全绿

---

## 1. 测试目标

1. 保障本期（主流程、车管、销售、续租）诉求在生产数据下稳定运行，回归零阻断缺陷。
2. 把"接口级冒烟"扩展为分层、可重复执行的测试体系，每次发版前 30 分钟内完成核心回归。
3. 覆盖当前测试空白：前端 UI 交互、并发与幂等、导入导出、数据迁移、权限边界穷举。

### 2.2 范围外（Out of Scope，本期）

- 运营段、财务段、超管段的新诉求调整（按 8.25 文档暂缓）
- 佣金转车租（诉求 32 明确不纳入）
- 应收公式重算（诉求 34，随财务段确认后单独立项）
- 正式环境压测（本期仅做基准性能摸底）

## 3. 测试策略与分层

### 3.1 分层模型

| 层级 | 工具 | 现状 | 目标 | 说明 |
| --- | --- | --- | --- | --- |
| L1 单元/纯函数 | pytest（现有） | 已覆盖指导价、折算、核销瀑布流等 | 保持并补强 | calculate_prorated_rent、guidance_base_candidates、尾板/基准车型规范化等纯函数优先补 |
| L2 接口集成 | Flask test_client（现有 70 例） | 主流程覆盖良好 | 每迭代新增诉求必配用例 | 独立临时库，setUp 重建 schema |
| L3 接口冒烟（类生产） | urllib/curl + 独立临时库（已有脚本） | 58 项六流程 | 扩展至 10 条流程、纳入发版 checklist | 与 L2 差异：走真实 HTTP+会话，验证登录/权限装饰器真实生效 |
| L4 前端 UI/E2E | 暂无 → 引入 Playwright | **空白** | 覆盖五角色关键路径 20 条 | 见 3.3 |
| L5 非功能 | 手工 + 脚本 | **空白** | 性能摸底、并发幂等、安全基线 | 见第 6 章 |

| --- | --- | --- | --- |

### 3.3 前端 UI/E2E 计划（Playwright 新引入）

现状：前端为零自动化覆盖，9,179 行单页全靠手工。引入 Playwright（Chromium 即可），先覆盖 P0 路径：

| 编号 | 路径 | 要点 |
| --- | --- | --- |
| UI-01 | 五角色登录+工作台 | 登录后页面清单与 seed role_pages 一致；无权限菜单不可见 |
| UI-02 | 销售报单表单 | 车牌号非必填可创建；车牌/车架/收款公司模糊下拉；VIN 后几位带出整车信息 |
| UI-03 | 出库操作 | 未传照片按钮拦截提示；传照后出库成功、状态即时刷新 |
| UI-04 | 审批中心 | 各角色只见待自己审批的步骤；操作列宽度不截断按钮（历史回归点） |
| UI-05 | 台账/客户库筛选 | 5+8 个筛选项组合查询、清空还原 |
| UI-06 | 黑名单提示 | 选黑名单客户时报单页弹出原因+标记时间 |
| UI-07 | 表格通用 | 长文本不溢出、操作列 fixed 不错位、移动端 375px 不横向滚动 |

落地方式：`tests/e2e/` 目录 + `playwright` pytest 插件，独立临时库起服务后跑；CI/发版前执行。

## 4. 权限测试矩阵（P0，每次发版必跑）

对 148 个接口按"角色×动作"穷举断言（脚本化：遍历路由表 + require_role 装饰器提取，自动生成应允许/应拒绝用例）：

| 角色 | 入库 | 报单 | 审批 | 财务确认 | 合同上传 | 出库 | 核销 | 发票申请 | 开票 | 指导价 | 黑名单标记 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 老板 | ✓ | - | ✓ | - | - | - | - | - | - | ✓ | ✓ |
| 运营 | ✓ | - | - | - | ✓ | - | 发起 | ✓ | - | ✗ | ✗ |
| 财务 | ✗ | - | - | ✓ | - | - | 核销 | - | ✓ | ✗ | ✗ |
| 车管 | ✗ | - | - | - | - | ✓ | - | - | - | ✗ | ✗ |
| 销售 | ✗ | ✓ | - | - | - | - | - | - | - | ✗ | ✗ |

另含数据范围断言：销售跨客户访问合同/催收/应收一律 403；页面级（role_pages）与动作级（role_actions）双重校验。

## 6. 非功能测试（摸底性质）

| 类型 | 场景 | 通过标准（建议） |
| --- | --- | --- |
| 性能基准 | 对账列表/客户库/台账在大数据量（车辆 5k、账单 50k）下响应 | P95 < 2s；N+1 查询清单输出 |
| 并发幂等 | 两人同时出库同一车、同时核销同一账单 | 一方成功一方 400，数据不错乱（现状 SQLite 串行写基本安全，迁 MySQL 后必测） |

| 文件上传 | 超大文件、非法类型、附件 >10 个限制 | 400 且不留半成品记录 |

## 9. 准入/准出标准

- **提测准入**：诉求文档条目可逐条映射到接口/页面；pytest 全绿；新增代码附带 L2 用例。
- **发版准出**：P0/P1 用例 100% 通过；六流程冒烟 100% 通过；权限矩阵无新增越权；备份已完成；阻塞/严重缺陷 = 0。
- **缺陷分级**：阻断（主流程走不通/数据错乱）、严重（权限越权/金额错误）、一般（校验提示缺失）、轻微（UI 瑕疵）。阻断/严重不过夜。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| app.py 单体 14.5k 行，改动牵一发动全身 | 回归漏测 | 发版必跑全量 70+ 用例与六流程冒烟；新功能优先加 L2 用例 |
| 前端零自动化 | UI 回归靠人肉 | Playwright 按计划补齐 P0；每版手工走查清单兜底 |
| SQLite→MySQL 迁移中 | 行为差异（事务/日期/游标） | 双库跑同一 L2 套件对比，差异清单逐项消化 |
| 减免/应收公式口径未最终确认 | 财务数据返工 | 相关用例标 P2 并打"口径待确认"标记，确认后启用 |
| 正式数据敏感性 | 测试污染 | 任何验证只用备份副本；冒烟脚本固定临时库路径 |

## 一、结论摘要

**整体评价：主流程骨架与流程图高度一致（10 项核查中 6 项完全一致、1 项基本一致），但存在 3 处实质性偏差和 1 处缺失，其中「比例指导口径」的移除是昨天指导价改版的直接结果，属于**有意的业务回归**，而流程图未同步更新。**

| # | 流程段 | 一致性 | 说明 |
|---|---|---|---|
| 1 | 指导价/指导口径校验（K1 节点） | ❌ **不一致** | 比例口径已移除，只比"报价 < 指导价" |
| 2 | 整车销售跳过指导价校验（K 节点） | ❌ **不一致** | 整车销售仍会触发价格特批 |
| 3 | 报单状态流转 / 财务确认 activate | ✅ 一致 | 5 状态 + 5 类审批流齐全 |
| 4 | 合同创建时机（Q 节点） | ✅ 基本一致 | 正式合同在运营上传时创建；另有"报单计划中"壳 |
| 5 | 首次付款不足额 → 老板审批 → 退款 | ⚠️ **部分一致** | 不足额挂应收/老板审批/驳回都在；**退款执行缺失** |
| 6 | 出库流程与状态（AD-AI） | ✅ 一致 | 车辆 租赁中/以租代售/已售，销售直接已结清 |
| 7 | 还款/催收（少还挂应收+万5滞纳金、多还预抵） | ✅ 一致 | 滞纳金逐日真实计提，减免链完整 |
| 8 | 退车审批链（AS-AZ） | ✅ 一致 | 六步链 + 审批中心合成 |
| 9 | 过户流程（AT-BB） | ✅ 一致 | 自然过户 + 提前结清自动生成过户单 |
| 10 | 老板查看全过程（AA 节点） | ❌ **缺失** | 只有全局审计日志（限100条），无单车全过程时间线 |

## 二、发现的 4 个问题（按严重度排序）

### 🔴 问题 1：比例指导口径已整体移除，流程图 K1 节点完全失效（最严重）

**现状（代码）**
- 4 个比例字段 `lease_deposit_ratio / lease_repayment_ratio / sale_down_payment_ratio / sale_repayment_ratio` 已被昨天（8-01）指导价改版从**所有业务代码**移除：`calculate_guidance_check`（[app.py:272](app.py#L272)）现在只做价格映射，`needs_approval` 恒为 `False`、`checks/missing/below` 恒为空数组。
- 真正的价格审批判断在 [app.py:3820-3828](app.py#L3820)：
  ```python
  needs_boss_price_approval = (
      not is_draft
      and (guidance_check['needs_approval']     # 恒 False
           or bool(guidance_check['missing'])   # 恒 False
           or is_price_below_guidance(quote_price, guidance_price)  # 报价 < 指导价
           or guidance_price <= 0)              # 缺指导价
  )
  ```
- 4 个字段仅残留在建表 DDL（[database.py:323-326](database.py#L323)）和 ALTER 迁移（[database.py:1040-1043](database.py#L1040)），**无任何业务代码读取**。
- 前端指导价弹窗也只维护 `guidance_price / lease_installment_price / sale_total_price` 三项（无比例输入）。

**与流程图矛盾**
- 流程图 K1「首付/押金比例和每期还款比例是否均不低于老板指导口径」、M1「读取当前老板指导比例口径」、global.mmd G-H 节点「老板维护指导比例口径 → 新报单按最新比例口径判断」全部失效。

**影响评估**
- 现在的实际规则是：**租赁/以租代售/整车销售统一按"报价 < 车型指导价（sale_total_price 或 lease_installment_price）"判断是否走老板价格特批**。
- 这是**有意的业务回归**（昨天改版），不是 bug。但若业务流程仍依赖"押金比例 ≥10%、每期还款比例 ≥2.5%"这类口径，则现在**已不校验**，低价高押、高杠杆报单会直接进入财务确认（只要报价不低于指导价）。

### 🔴 问题 2：整车销售并未跳过指导价校验（K 节点与代码相反）

**现状（代码）**
- 流程图 K 节点「是：整车销售不做指导价确认 → 直接财务确认」。
- 但代码 `normalize_sales_mode`（[app.py:215](app.py#L215)）把 `整车销售/卖车/销售` 归一为 `销售`，而 `calculate_guidance_check` 对销售模式取 `display_guidance = guidance['sale_total_price']`（[app.py:283-285](app.py#L283)），**整车报价低于 sale_total_price 指导价时照样 `待价格特批`**。
- `needs_boss_price_approval` 没有按销售模式分支。

**影响评估**
- 若整车销售允许低于指导价成交（实际业务中常见），现在会被价格特批卡住，与流程图设计意图相悖。
- 建议确认：整车销售是否应豁免价格特批？若应豁免，需在 `create_sales_order` / `update_sales_order_draft` 中加 `mode=='销售'` 分支。

### 🟠 问题 3：首次付款不足额被驳回后，「老板发起退款 → 财务执行退款」未落地

**现状（代码）**
- 流程图 T 不足额 → W 报实收/原因/承诺时间 → X 挂应收 → Y 老板审批 → 不同意 → AA 老板发起退款 → AB 财务执行退款 → AC 本单结束。
- 代码中**前半段齐全**：
  - 不足额自动挂应收 `create_or_update_receivable(...,'initial_payment_shortfall',...)`（[app.py:653](app.py#L653)）；
  - 承诺期内不计滞纳金、超期按万5/日计提（[app.py:1966-1994](app.py#L1966)）；
  - 老板审批不足额出库 `initial_payment_shortage`（[app.py:6941](app.py#L6941)）。
- **后半段缺失**：老板驳回后（[app.py:7059-7080](app.py#L7059)）只做"首付状态已驳回、合同已终止、车辆释放回在库、报单已作废"，**没有任何退款出款接口/退款流水落库**。
- 对比退车流程有完整的 `pay_return_refund`（[app.py:6384](app.py#L6384)）写 `refund_serial / refund_paid_amount`，首次付款驳回路径没有对应实现。

**影响评估**
- 客户已付的首付款在驳回后**没有系统化的退款记录与出款闭环**，财务只能线下处理。建议补充与退车一致的退款执行环节。

### 🟡 问题 4：老板「查看全过程」能力缺失（AA 节点）

**现状（代码）**
- 流程图 AA「老板端查看全过程：入库、报单、比例口径、审批、合同、首付、出库、对账、退车、过户、利润」。
- 代码仅有：
  - `GET /api/audit-logs`（[app.py:5778](app.py#L5778)）：全表最近 100 条，无按单/按车筛选，无时间线组织；
  - `GET /api/boss-dashboard/overview`（[app.py:4994](app.py#L4994)）：汇总指标 + 待办统计；
  - `GET /api/profit/by-vehicle`：单车利润（[app.py:4938](app.py#L4938)）。
- **未找到**把 `audit_logs` 按 VIN/合同串成时间线的界面或接口。

**影响评估**
- 老板要追溯单车全生命周期只能靠业务表状态字段 + 全局日志拼凑，体验与流程图设计不符。建议加一个「单车/单单时间线」接口（按 sales_order_id 或 vehicle_id 聚合 audit_logs + 状态变更）。

## 四、根因分析：为何会不一致

1. **比例口径移除是昨天（8-01）指导价改版的直接结果**：`git diff 9a782e5` 显示 `calculate_guidance_check` 的 `checks/below/missing/needs_approval` 全部被清空，4 个比例字段从 SQL、前端表单、通知文案中一并删除。**业务决定正确，但流程图（6.2-main-flow.mmd 等）未同步更新**，导致文档落后于代码。
2. **整车销售特批豁免**：可能是改版时未考虑整车销售的业务豁免需求，属遗漏。
3. **退款闭环**：首次付款驳回路径长期只有"终止"，退款执行一直是线下操作，未代码化。
4. **全过程查看**：老板端一直缺时间线视图，流程图超前于实现。

## 五、建议（按优先级）

### P0：流程文档与代码对齐（半天）
- 更新 `6.2-main-flow.mmd` / `global.mmd` / `rental.mmd` / `lease-to-sale.mmd` / `sale.mmd` 中 K/K1/M/M1/G-H 节点：
  - 删除"首付/押金比例、每期还款比例"口径判断，改为**「报价是否低于车型指导价」**；
  - 删除"老板维护指导比例口径"节点，改为"老板维护车型指导价（整车价/租赁月供）"；
  - 明确整车销售是否豁免（视业务决定）。

### P1：确认整车销售是否豁免价格特批（半天）
- 若业务上整车销售允许低于指导价成交 → 在 `create_sales_order`（[app.py:3820](app.py#L3820)）与 `update_sales_order_draft`（[app.py:4000](app.py#L4000)）加 `mode=='销售'` 豁免分支。
- 若不允许（整车销售也须报批）→ 保持现状，仅更新文档说明。

### P2：补首次付款驳回后的退款闭环（1 天）
- 参考退车 `pay_return_refund`（[app.py:6384](app.py#L6384)），在老板驳回首付不足出库（[app.py:7059](app.py#L7059)）后增加退款执行接口：写退款流水（serial/金额/账户/时间/经办人）、合同标记已退款、日志留痕。

### P3：老板端「单车全过程时间线」（1-2 天）
- 新增 `GET /api/vehicles/<id>/timeline` 或 `GET /api/sales-orders/<id>/timeline`：聚合 `audit_logs`（按 ref_id/vehicle_id）+ 报单/合同/首付/出库/还款/退车/过户各状态变更，前端老板页新增"全过程"抽屉。

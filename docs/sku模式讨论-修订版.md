> **修订说明（V3.2）**：
> 1. **业务边界**：本项目**只做「以租代售」与「租赁」两种模式**，不涉及整车销售。代码中残留的销售模式分支（`normalize_sales_mode` 对'销售'的映射、`calculate_guidance_check` 的销售防御分支、合同表单中的"新车销售"单选项、车辆状态`已售`、出库 `status_map` 中的 `'销售':'已售'` 等）属于历史遗留，按本版文档应逐步清理，**文档不再描述销售模式**。
> 2. **底盘车业务规则**：底盘车 = 直接从车场购入的**无厢体车头**（纯车头，无尾板）。它**不能直接用于租赁/以租代售**，业务上一定是「车头 + 客户选定厢体 → 装配 → 成整车」后出租/以租代售。因此：底盘车在库中作为**车头存货**存在，出库/报单前必须配置厢体；底盘车本身**不进入指导价维护与待维护提醒**（代码已实现排除）。
> 3. **以租代售定价**：只保留**管理端直接维护金融方案**（首付/每期/期数）这一条路径。**`sale_total_price`（以租代售整车价）为历史错误开发，予以删除**，不再出现在文档数据模型与流程中（代码保留仅作展示/兼容，文档按删除目标描述）。
> 4. **车辆状态**：删除「已售」，`已售/已过户` 更名为 **「已过户」**——该状态仅由**以租代售提前结清→过户**触发（代码 `create_ownership_transfer` 仅允许以租代售合同过户，`complete_ownership_transfer` 将车辆置为 `已售/已过户`），命名与业务语义对齐。
> 5. **以租代售方案范围（V3.3）**：金融方案不是基准车型通用价。每条方案必须绑定「**基准车型 + 新车 + 厢货/宽体/高栏/冷藏/平板**」之一；二手车和底盘车不支持以租代售方案。销售报单仅可选择与 VIN 所属新车厢型完全一致的启用方案。
> 6. **基准车型口径（V3.4）**：尾板是基准车型身份维度，取值仅为「有 / 无」；成色、厢型是子型号维度，不能混入基准车型。纯电与混动/燃油车的规格字段互斥，界面与接口均只允许维护当前能源类型适用的字段。
> 7. **编辑器约束（V3.5）**：车辆编辑页中的成色、尾板使用固定枚举；品牌、品系、厢型及能源专属基准车型字段必须从启用的数据字典中选择。`fuel_form` 是采购导入确定的能源依据，只读展示；即使绕过界面提交，车辆更新接口也不会改写它。

## 1. 业务背景与目标

### 1.1 业务模式（仅两种，无整车销售）

- **车辆租赁（经营租赁）**：客户按月支付租金获得车辆使用权。报价需核对「押金 + 月供」双维度不低于老板维护的指导价。
- **以租代售**：客户支付首付后按月支付租金，约定期满（或提前结清）后所有权转移给客户（过户）。报价时选择老板按**新车子型号**维护的金融方案（首付/每期/期数），**无价格特批**。

### 1.2 核心目标

建立准确、高效、贴合真实库存的车辆规格与定价管理体系：

- 车辆规格按能源类型定义基准车型：纯电关注电池品牌和电池度数；混动/燃油车关注马力和档位；两类字段不得混填。
- 销售价格按两种方式分别定义：租赁 = 押金 + 箱型5选1月供 + 尾板加价；以租代售 = 金融方案（首付/每期/期数）。
- 销售报单从**真实库存车辆（VIN）**发起，系统自动带出车型与指导价。
- 管理端维护车型指导价（基准车型归一化），未维护时通过「待维护提醒」驱动补全。

| 能源类型 | 基准车型组成 | 不适用字段（接口禁止混填） |
|---------|-------------|----------------------------|
| 纯电 | `品牌 + 品系 + 电池品牌 + 电池度数 + 尾板(有/无)` | 马力、档位 |

**车辆编辑交互（V3.5）**：

- 成色固定为「新车 / 二手车」，尾板固定为「有 / 无」。
- 品牌、品系、厢型使用通用启用字典；纯电只显示并使用「电池品牌 / 电池度数」字典，混动和燃油车只显示并使用「马力 / 档位」字典。
- 燃料形式、VIN、系统计算的基准车型只读。燃料形式如有数据问题，应由采购导入源修正后重新导入，而不是在业务编辑页切换能源类型。
- 颜色仍是车辆实例修正字段；驾驶室及其余采购追溯字段不参与基准车型、SKU 或数据字典。

> **模板数据分析要点**（深入分析 20260804 模板所得）：
> - 模板 1081 行数据、789 行有效（292 行为公式/说明/空行）；表头第2行，数据第4行起。
> - **填充规律**：纯电车填「电池度数+电池品牌+新能源动力电池型号+驱动电机型号」，油/气/混动车填「马力+发动机厂家及功率+变速箱厂家及型号」——即**按能源类型分叉填充**，与 V3.0 文档"能源类型不同属性不同"的设想天然吻合，只是由模板列承载而非独立字典。
> - 「厢尺寸」列模板中全空，只做历史导入兼容，不在车辆编辑、数据字典、车型或 SKU 中使用。
> - 「档位」作为混动 / 燃油车的基准车型维度；纯电车型不显示、不维护该字段。
> - 「尾板」列只有"带尾板"（102 行，分布在冷藏61/厢货39/高栏2），无"无"值 → 空即无尾板。

### 3.2 车型指导价（`model_guidance_prices`，核心实体）

按**基准车型**维护租赁定价；同一基准车型按成色共享押金和尾板加价，并按厢型维护月供。

**基准车型归一化规则**（`normalize_base_car_type`）：
- 去成色前缀：`新车` / `二手车` 开头 → 去掉（`strip_condition_prefix`）
- 去厢型后缀：`厢货 / 宽体 / 高栏 / 冷藏 / 平板 / 底盘` → 去掉（`strip_box_suffix`）
- 尾板不剥离：`带尾板` 统一为 `有尾板`；历史车型没有尾板值时，归一为 `无尾板`
- 示例：`新车解放J6F锡柴130LNG厢货` → 基准 `解放J6F锡柴130LNG无尾板`；`新车解放J6F锡柴130LNG冷藏带尾板` → 基准 `解放J6F锡柴130LNG有尾板`

### 3.4 车辆实例与库存（已实现）

车辆实例表 `vehicles` 数据由采购端按 25 列固定模板导入，销售端只读。车辆状态流转：

| 状态 | 说明 | 触发 |
|------|------|------|
| 在库 | 可发起报单 | 入库 / 退款闭环 / 退车入库 |
| 报单锁定中 | 已提交报单未出库 | 创建报单（非草稿） |
| 待出库 | 合同审批通过等待出库 | 合同流程 |
| 租赁中 | 租赁合同已出库，履约中 | 出库（deliver_vehicle） |
| 以租代售 | 以租代售合同已出库，履约中 | 出库（deliver_vehicle） |
| 已过户 | 以租代售提前结清/期满过户完成 | 完成过户（complete_ownership_transfer） |
| 退车中 | 退车验收中 | 发起退车 |

> **V3.2 变更**：删除「已售」状态（整车销售下线）；原 `已售/已过户` 更名为 **`已过户`**。该状态仅由**以租代售合同过户**触发（代码 `create_ownership_transfer` 校验 `contract_type == '以租代售'` 才允许发起过户；`complete_ownership_transfer` 将车辆置为 `已售/已过户`），命名与语义对齐。当前库中仅 在库/报单锁定中 两种状态（业务运行初期）。

### 4.2 导入规则（已实现）

- **表头定位**：自动在前 10 行中查找包含 "VIN" 且含 成色/品牌/产品名称/经销商 的行作为表头（第 2 行）；找不到时兜底第 4 行。**按表头中文名匹配列**，列顺序变化不影响（`VEHICLE_HEADER_MAP`）。
- **VIN 校验**：17 位，重复 VIN 自动跳过（不入库）。
- **电池度数/电池品牌推导**：电池度数/品牌为空时，从「新能源动力电池型号」自动推导（kWh 向下取整 + 度：61.1kWh→61度、100.46kWh→100度；品牌取型号前 2 字：宁德/力神/弗迪）。
- **基准车型计算**：纯电使用品牌+品系+电池品牌+电池度数+尾板；混动/燃油车使用品牌+品系+马力+档位+尾板。成色、厢型及厢尺寸不参与计算。
- **字典校验**：入库时校验车型是否已在指导价字典中（`normalize_base_car_type` 归一化后查 `model_guidance_prices`），不在则标记 `validation_status='invalid'`，**不影响入库**，但该车无法发起报单。
- **缺指导价提醒**：未匹配到指导价的车辆写入审计日志「缺少指导价提醒」，汇总到设置页「待维护指导价车型」红色提醒列表。
- **旧模板兼容**：兼容 产品名称（→car_type）、结算价格/结算价/购买价（→purchase_price）、技术路线、经销商代码 等旧列名。
- **角色**：仅 车管/老板 可导入。
- **导入结果**：返回 成功/重复跳过/失败 计数 + 明细（含字典校验状态），前端展示明细表格。

## 5. 底盘车业务规则（V3.2 明确）

**底盘车 = 直接从车场购入的无厢体车头**（`box_type = 底盘`，模板中 179 辆/约23%；代码中 24/47 辆）。关键业务规则：

1. **底盘车不能直接租赁/以租代售**：租赁与以租代售一定是「车头 + 客户选定厢体 → 装配成整车」后执行。底盘车作为**车头存货**存在。
2. **底盘车不进入定价体系**：底盘车（纯车头）本身无厢体，无法套用「箱型5选1月供」；因此**不进入指导价维护下拉**（`modelGuidanceCarTypeOptions` 排除 `box_type=底盘`）、**不进入待维护指导价提醒**（`guidance-price-alerts` 排除底盘）、不参与「按厢型取月供」的报单价格核对。
3. **报单约束**：底盘车如需报单，需先通过车辆编辑补全/修改厢型为实际厢体（如"厢货"），或业务上装配完成后再入库为整车。底盘车本身发起报单时无法选择箱型月供，应提示先配置厢体。
4. **归一化关系**：底盘车型同样走 `normalize_base_car_type` 归一到基准车型（`新车解放J6F锡柴130LNG底盘` → `解放J6F锡柴130LNG无尾板`），与同基准的带厢车共享指导价字典，但**月供取数依赖厢型列**，底盘无对应箱型列故不取月供。

> 上述第 1/3 条为**业务规则确认**（文档明确约束）；第 2/4 条为代码已实现行为。

- **租赁指导价 Tab（子型号完备性表）**：
  - 表格固定列出该基准车型的 **新车/二手车 × 厢货/宽体/高栏/冷藏/平板** 共 10 个子型号，不论该子型号是否已有库存或已配置指导价。

## 7. 销售端：报单与合同流程（已实现）

### 7.1 报单起点：从库存车辆发起

**销售报单必须从具体车辆（VIN）发起**，不能凭空按规格选车：

- 车辆管理页/车辆列表 → 在库车辆 → 点击「发起报单」。
- 系统自动带出：VIN、车型(car_type)、品牌、品系、颜色、厢型、车牌号、网员价、出厂价等。
- 校验：仅在库/报单锁定中可发起；字典校验不通过（车型未维护指导价）不可发起；同一 VIN 不可重复报单（未结清合同/他人锁单拦截）；客户黑名单拦截。

### 7.2 报单表单（已实现）

销售在报单弹窗中填写：

1. **销售方式**：以租代售 / 经营租赁（二选一，**无整车销售选项**）。
2. **客户信息**：姓名、电话、身份证号。
3. **车辆信息**（从车辆带出，可微调）：成色、车架号、品牌、品类、驾驶室、电池/发动机、功率/电池度数、变速箱/档、颜色、厢型、尾板。
4. **分期信息**：
   - 以租代售：选择老板维护的**金融方案**（下拉仅显示该 VIN 的基准车型、**新车**、实际厢型三者一致的启用方案，显示 方案名(首付/每期×期数)），选后自动带出首付、每期价、期数。
   - 经营租赁：填写押金金额 + 每期租金（月供）+ 租期 + 起租日；页面实时显示指导价（押金/月供）并警告「低于指导价」。
5. **首次付款**：报单时一并提交，显示应付首付（租赁=押金+首月月供；以租代售=方案首付），上传客户付款截图；不足需填写原因+承诺归还日期。

### 7.3 提交与审批（已实现）

- **租赁**：押金或月供任一低于指导价 → 报单进入「待老板审批」（价格特批），老板审批通过后转财务确认。
- **以租代售**：选金融方案即无需价格特批；首付不足另走首付不足特批。
- **快照**：报单提交时锁定 金融方案/租赁押金指导价/箱型月供指导价，方案后续变更不影响已出库车辆。
- 财务确认到账 → 生成客户分期计划 → 运营上传线下合同 → 交付（首付款/出库）。

### 7.4 合同与 VIN 绑定（已实现）

- 合同从报单创建（销售报单 → 财务确认 → 运营上传线下合同），车辆 VIN 已在报单阶段绑定。
- **合同类型仅 租赁 / 以租代售 两种**（整车销售已下线；直接创建合同时的"新车销售"单选项按 V3.2 应移除）。
- 合同车辆一致性校验：合同必须关联报单车辆，报单车辆与合同车辆不一致则拒绝。
- 交付流程：出库前需上传出库照片+出库单照片 → 出库后车辆状态变更（租赁→租赁中 / 以租代售→以租代售）。

### 7.5 以租代售过户（已实现）

- 仅**以租代售**合同可发起过户（`create_ownership_transfer` 校验合同类型）。
- 提前结清或期满后：运营发起过户 → 填写过户日期/新车主/证件 + 上传过户文档 → 完成过户。
- 完成后：合同状态置为「已结清」，车辆状态置为 **「已过户」**（代码当前为 `已售/已过户`，按 V3.2 更名）。

## 8. 关键规则与异常处理（已实现）

1. **定价匹配**：租赁指导价以 `normalize_base_car_type`（去成色前缀 + 去厢型后缀）匹配基准车型，再按成色和厢型取价；以租代售方案除基准车型外，还必须精确匹配「新车 + 实际厢型」。兼容拼接格式（`XX / YY / 厢货`）。提交以租代售报单时，所选方案必须属于该 VIN 的完整子型号。
2. **租赁双维指导价**：押金与月供（箱型5选1+尾板）**两者都不能低于指导价**，任一低于 → 老板价格特批。尾板加价默认 300 元（可用 `tail_plate_price` 覆盖）。
3. **以租代售无特批**：选金融方案即可，无"低于指导价"审批；首付不足另走首付不足特批。
4. **定价未覆盖**：车型不在指导价字典中 → 车辆标记 invalid → **不可发起报单**；管理端设置页红色提醒驱动维护。
5. **VIN 唯一性**：同一 VIN 同一时间只能处于一个有效报单/合同下（未结清合同不可重复报单、报单锁车防二次报单、合同车辆不可重复签约），避免一车多卖。
6. **方案变更**：以租代售方案/指导价变更后，**已出库车辆按变更前快照执行**，库中车辆按新方案执行（报单快照机制）。
7. **底盘车**：无厢体车头，不直接租赁/以租代售；不进入指导价维护与待维护提醒（见第 5 节）。

## 模块 A — 用户与权限

### A1 登录 / 登出
- **触发**:用户访问任意非 `/login` 路由。
- **输入**:用户名、密码。
- **规则**:命中 `users.is_active=1` 才能登录;失败仅返回"账号或密码错误",不区分。
- **输出**:写入 session,返回 `display_name`、`role`、`role_pages`、`role_actions`。
- **异常**:连续 5 次错误锁定 10 分钟(可选做)。

### A2 角色矩阵(对照 5.27 流程,v2 修订)

| 角色 | 工作台主功能 | 关键不可见数据 |
|---|---|---|
| 销售 | 报单、催款 T+7、减免申请(租金/滞纳金)、退车发起、提前退车/结清、报价单查看 | 采购价、税率、返利、毛利/净利、单车盈利 |
| 财务 | 报单确认、厂家表上传与比对、首款流水回填、还款核销、减免复核执行、发票开具/作废/重开、返利录入、退车押金、提前结清收款 | — |
| 运营 | 合同 PDF 上传、催款 T+3、本期还款上传、发票申请、过户登记、提前结清本金计算、多还抵扣月份与客户确认 | 采购价、税率、返利、毛利/净利 |
| 车管 | 入库、出库、验车 | 价格类全部 |
| 老板 | 双指导价维护、价格特批、退车领导审批、租金/滞纳金减免审批、全过程穿透、返利全量可见 | — |

> **决策项 32**:**销售视角永不展示盈利/采购价/返利**,无论合同是否已结清。盈利数据仅财务、老板可见(详见模块 P、U)。

### A3 操作审计
- **触发**:任何状态变更类接口被调用。
- **规则**:写 `audit_logs(action, target_type, target_id, detail, operator, ip_address)`。
- **不能跳过的动作清单**:报单创建/审批/驳回/作废、合同生成、计划比对、还款核销、减免申请/审批/执行/撤销、发票开具/作废/重开、退车节点、过户、出库、返利、指导价维护、黑名单维护(详见模块 S)、字段级权限变更。

### A4 字段级权限
- 见模块 U(字段级权限矩阵),由前端组件按角色 + 字段动态渲染,后端在 DTO 层做兜底过滤。

## 模块 B — 车辆资产管理

### B1 车辆入库
- **触发**:车管端"新增车辆"。
- **输入**:VIN(17 位,必填唯一)、车牌、车型、车厢、电池、是否新车、开票价、采购价、税率、月折旧期数、保险到期、年检到期、附件(发票/合同 PDF)。
- **规则**:
  1. VIN 长度=17,必须大写;重复返回"该 VIN 已入库"。
  2. `status` 初始化为 `在库`,`activated_at=NULL`(新车)或当前(二手)。
  3. 系统按"开票价 × 残值率"自动算 `estimated_residual_value`。
  4. 若车型在 `model_guidance_prices` 已维护双价,则不要求录入单车指导价。
- **输出**:车辆主数据 + 入库审计日志。
- **异常**:VIN 长度错;车型主数据缺失时仅警告,不阻塞。
- **界面要点**:车辆入库后即可在销售端"在库车辆下拉"中选择。

### B2 车辆状态机(v2 修订,决策项 6)

```
在库 ──报单创建──> 报单锁定中 ──报单驳回/作废──> 在库
报单锁定中 ──出库(租赁)──> 租赁中
报单锁定中 ──出库(以租代售)──> 以租代售
租赁中 ──退车发起(M1)──> 退车中 ──车管验车(M2)──> 待维修(若验车判定需修) / 在库(若无问题)
以租代售 ──结清+过户──> 已售/已过户
以租代售 ──提前结清+过户──> 已售/已过户
待维修 ──维修完成──> 在库
租赁中 / 以租代售 ──事故报修(运营登记,合同存续期内)──> 维修中 ──修复──> 租赁中 / 以租代售
```

> **修订要点**:
> - **删除**了 v1 中"租赁中/以租代售 ──维修──> 待维修"的直接路径。租赁/在售期间发生事故仅切换为 `维修中`(临时维修态,不影响合同),修复后回到原营业态。
> - **`待维修` 仅作为退车验车后的中转态**,由 M2 验车结果决定。
> - 新增 `退车中` 显式状态,贯穿 M1~M5,M6 出款完成后才落库。

### B3 车辆查询
- **角色**:全员可见列表(含老板穿透),不同角色看到的字段集不同(详见模块 U)。销售不见采购价、税率、返利、盈利相关。
- **筛选**:VIN、车牌、车型、状态、公司、车厢、是否新车。
- **导出**:Excel(老板/财务)。

## 模块 C — 指导价管理(双价 + 版本)

### C1 维护"租赁每期分期指导价"
- **触发**:老板端 `/admin/guidance-prices/lease`。
- **输入**:车型、租赁分期指导价(元/期)、备注、生效时间(默认即时)。
- **规则**:
  1. 写 `model_guidance_prices.lease_installment_price`,旧值入 `model_guidance_price_history(price_kind='lease_installment')`。
  2. **存量订单不变价**:已生成的报单/合同上的双价快照锁定在"报单提交时刻"。
  3. **新增报单按最新价**:任何"待价格特批驳回 → 重新报单"也按调整后最新价。
- **输出**:历史记录 + 影响车辆数(同车型在库数)。
- **异常**:价格 ≤ 0 不允许保存。
- **界面要点**:旁边显示该车型当前在库数、在租数。

### C2 维护"以租代售整车指导价"
- 与 C1 一致,字段=`sale_total_price`,`price_kind='sale_total'`。

### C3 指导价缺失硬性阻塞(决策项 9)
- **触发**:销售端进入"新建报单"或保存草稿。
- **规则**:
  - 若所选 VIN 对应车型的双指导价**任一为空或 ≤ 0**,**禁止提交报单**(草稿可保存但不能进入审批流),前端弹窗提示"请联系老板维护车型指导价"。
  - 老板工作台首页新增"指导价缺失"红色提醒卡片,列出在库且车型缺指导价的车辆数,点击直达 C1/C2 维护页。
- **输出**:阻断报单流程,保留草稿。
- **异常**:历史数据(在租中已无指导价)不阻塞,仅在老板看板提醒。

## 模块 D — 销售报单(租赁 / 以租代售)

### D1 报单状态字典(v2 简化,决策项 8、24)

| 状态 | 含义 | 说明 |
|---|---|---|
| `草稿` | 销售保存未提交(决策项 10) | 可反复编辑、删除;不锁车 |
| `待价格特批` | 报价低于指导价,等待老板 | **锁车** |
| `待财务确认` | 价格通过,等待财务比对计划表与确认 | **锁车** |
| `已激活` | 财务确认完成,合同/计划落库 | **锁车** |
| `已作废` | 终止态(驳回、撤回、作废统一收口) | **释放车辆** |

> **决策项 8**:删除原"价格特批驳回""财务驳回"两个独立状态,合并到 `已作废`(操作日志内区分原因)。
>
> **决策项 17**:**老板特批驳回 = 直接置 `已作废`,不允许在原报单上重提**;销售如需修改后再报,通过"以草稿复制"生成新报单。

### D2 草稿保存与失效(决策项 10、26)
- **触发**:销售端"暂存草稿"按钮。
- **规则**:
  1. 草稿允许多次编辑、删除,**不锁车**(避免一辆车被多个草稿同时占用)。
  2. 草稿生效期 7 天,过期自动作废(不影响库存)。
  3. **快照规则**:草稿不写入双价快照,仅在"提交报单"瞬间从 `model_guidance_prices` 读取最新值并写入 `sales_orders.snapshot_*`,确保快照永远反映"提交时点的最新指导价"。
  4. 若草稿对应车辆在保存期间已被其他报单锁定,提交时报错"该车辆已被其他报单占用",草稿保留供调整 VIN。
- **输出**:`sales_orders.order_status='草稿'`,`saved_at`、`expires_at` 落库。

### D3 新建报单(提交)
- **触发**:草稿点"提交报单"或直接"新建并提交"。
- **输入**:
  - 共同字段:VIN、客户、客户电话、收款公司(模块 R)、起租日、销售方式(租赁/以租代售)、销售顾问、备注、附赠物。
  - **租赁**:租期、月租金、押金、首期付款日。
  - **以租代售**:分期数、首付款、月租金、整车成交价。
- **规则**:
  1. 仅 `vehicles.status='在库'` 可报。
  2. 一辆车同时只能存在一个进行中的报单(状态 ∈ {待价格特批、待财务确认、已激活})。
  3. **报单提交即锁车**:`vehicles.status='报单锁定中'`。
  4. **客户黑名单校验**:命中模块 S 黑名单 → 直接拒绝提交,提示销售联系老板审核解禁。
  5. **指导价校验**(决策项 9):双价任一缺失直接拒绝。
  6. **价格核对**:
     - 租赁:`rent < lease_installment_price` ⇒ 触发特批
     - 以租代售:`sale_total_price < sale_total_price_guidance` ⇒ 触发特批
  7. 写入 `sales_orders` 并保存双价快照 `snapshot_lease_installment_price`、`snapshot_sale_total_price`(从最新指导价读取,见 D2)。
- **输出**:`order_status='待价格特批'` 或 `'待财务确认'`。
- **异常**:VIN 不存在 / 车不在库 / 已有进行中报单 / 黑名单命中 / 指导价缺失。
- **界面要点**:右侧实时显示当前两条指导价及差额预警条;客户被加入黑名单时弹窗提示。

### D4 报单作废
- **触发**:① 老板特批驳回(决策项 17);② 财务确认时发现严重问题(改为驳回);③ 销售主动撤回(状态=待价格特批/待财务确认时)。
- **规则**:
  1. 报单状态置 `已作废`,**车辆状态恢复 `在库`**。
  2. 销售可"复制"该报单到草稿,改价后重新提交(等同新报单)。
  3. 审计日志记录作废原因(驳回原因/撤回原因)。
- **输出**:`sales_orders.voided_at`、`void_reason`、`voided_by` 落库。

### D5 报单查询
- **筛选**:状态、销售方式、销售顾问、客户、时间区间。
- **批量动作**:仅老板可批量驳回(=作废);财务可批量确认(同状态)。

## 模块 E — 价格特批

### E1 老板特批
- **触发**:报单 `order_status='待价格特批'`。
- **输入**:通过 / 驳回 + 备注(驳回必填)。
- **规则**:
  1. 命中 `approval_flows.ref_type='price_exception'`,只一步,角色=老板。
  2. 通过后报单转 `待财务确认`,**车辆继续锁定**。
  3. 驳回直接进入 D4 作废流程(决策项 17)。
- **输出**:更新 `boss_price_approved_by/at`、`price_check_status='已通过'`。
- **SLA**(决策项 20):老板特批 24h 未处理 → 系统每日给老板发提醒;销售可主动催办,催办记录写 audit_logs。

### E2 财务确认报单(F→E 时序解耦,决策项 1)
- **触发**:`order_status='待财务确认'`。
- **前置**:必须先完成 F1(系统生成客户计划)、F2(财务上传厂家表)、F3(双表比对)且 `customer_plan_match_status='已通过'` 或"差异已确认"。
- **规则**:
  1. 财务核对客户计划与厂家计划比对结果,确认无误。
  2. 通过后 `order_status='已激活'`,触发 P 模块"单车盈利基础数据"生成,允许进入合同生成与还款计划落库。
  3. **驳回**:走 D4 作废流程,审计原因。
- **异常**:比对失败时不允许激活,前端提示具体差异列表(详见 F3)。
- **界面要点**:确认按钮旁显示"客户计划期数 vs 厂家计划期数 vs 比对状态"三段式徽章。

## 模块 F — 还款计划(双表生成与比对)

> **决策项 1(关键)**:F、E 时序在 v2 解耦。客户计划由"已激活"前置生成,即:**草稿/特批通过 → 待财务确认 → 系统生成客户表 → 财务上传厂家表 → 双表比对 → 比对通过 → 财务点击"激活报单" → `已激活`**。F 不再依赖 E2 完成,反而是 E2 的前置。

### F1 系统生成"客户还款计划表"
- **触发**:报单进入 `待财务确认`(由 E1 通过或非特批直接进入)后,系统自动写 `repayments(plan_kind='customer')`。
- **规则**:
  - **租赁**(决策项 14):
    - 第 1 期 `due_date = 起租日`(首期 + 押金已收,通常起租当日)。
    - 第 N 期 `due_date = 第 1 期 due_date + (N-1) × 月`。**租赁是否首期当月收取以合同条款为准**;若合同标记"首期延后",则按"次月起还"模式。
  - **以租代售**:第 1 期 `due_date = 起租日 + 1 月`(次月起还);共 `loan_periods` 期。
  - 金额=`rent`(每期月租)。
- **重算**:若财务在 E2 之前发现客户输入有误,要求销售改单 → 销售改单后 F1 自动重算并清空 F2、F3 结果,需要重新上传厂家表。

### F2 财务上传"厂家还款计划表"
- **触发**:F1 完成后,财务端"上传厂家计划表"按钮亮起。
- **输入**:Excel(沿用现有模板,识别"应还款日期/客户应还金额合计")。
- **规则**:解析后写 `factory_repayments(period, due_date, amount)`,期数自增。
- **异常**:模板表头识别失败提示"未识别到厂家还款计划表头"。

### F3 系统比对(v2 新公式,决策项 11)
- **触发**:F2 完成后自动触发,或财务点"重新比对"。
- **比对维度**:
  1. **总金额一致**:`Σ factory.amount ≈ Σ customer.amount`(允许利差/管理费区间)。
  2. **跨期归一化金额**:厂家与客户期数可能不同,采用"等额折算"——
     ```
     normalized_factory_per_period = (Σ factory.amount × factory_periods⁻¹) × (factory_periods / customer_periods)
     ≈ Σ factory.amount / customer_periods
     ```
     例:厂家 60 期 × 1000 元 = 60,000,客户 36 期 → 单期归一化 = 60,000 / 36 ≈ 1,667;与客户表单期 `rent` 比较是否在容差内。
  3. **首末期日期一致**:`factory[0].due_date == customer[0].due_date` 且 `factory[end].due_date` 与客户末期日期落在同一月。
- **输出**:`customer_plan_match_status ∈ {已通过, 差异待处理, 差异已确认}` + 差异行明细。
- **界面要点**:差异行高亮显示,允许财务点"以厂家表为准重算客户表"或"以系统客户表为准忽略差异(填写差异说明)"。
- **决策项 11**:差异说明纳入审计,通过后状态置"差异已确认"等价"已通过",可进入 E2。

### F4 进入财务确认
- **触发**:F3 通过/差异已确认。
- **规则**:进入 E2;E2 通过后报单 `已激活`,系统同时把 F1 的 `repayments` 表激活(`status='待还款'`)并触发 P 模块。

## 模块 H — 每日监控与催收

### H1 日终批处理(系统每日 00:30)
- **触发**:Cron 调度 `POST /api/jobs/daily-collect`。
- **处理顺序**:
  1. 拉取所有未结清 `repayments`(`status ∈ {待还款, 临近还款, 部分核销, 待催款, T+3运营已催, T+7销售已催, 逾期}`)。
  2. **T-3 预警**:`due_date - today = 3` ⇒ `status='临近还款'`,系统自动生成提醒文案并推送到运营工作台。
     - **自动生成文案模板**(占位符由系统填充):
       ```
       尊敬的{客户姓名},您的车架号为{VIN}的车辆将于{应还日期}进行还款,
       本期应还金额 ¥{应还金额}(第{期数}/{总期数}期),
       请您按时将款项转入收款账户:{收款公司}-{银行}-{账号}。
       如已支付请忽略本提醒,感谢您的配合。
       ——{公司名称}
       ```
     - **运营线上通知动作**:
       - 工作台"今日 T-3 预警"列表展示每条待提醒记录(车牌、客户、应还日、金额、文案预览)。
       - 运营点【发送提醒】可选择渠道:① 短信 ② 微信(企微/客户群)③ 复制文案手动发送。
       - 文案允许编辑(保存后写回,但保留默认模板版本)。
       - 发送后写 `notification_logs(repayment_id, channel, content, sent_by, sent_at, status)`,在该期还款时间线上展示。
       - 同一期 T-3 节点可多次发送,但工作台只显示"未提醒"列表;已提醒的用绿色徽标标记。
  3. **T 日**:由 I 模块覆盖。
  4. **T+1 起**:每日写 `late_fee_ledger`(见 J 模块,基于"原始未还本金"计提,决策项 5)。
  5. **T+3**:`status='待催款'→'T+3运营已催'`,生成运营催款任务 + 文案。
  6. **T+7**:`status='T+3运营已催'→'T+7销售已催'`,生成销售催款任务 + 文案;同时触发 H3 顺序扣款(押金/首付款抵冲,决策项 5)。
- **输出**:任务推送到对应工作台 + audit_logs。

### H2 催款执行
- **运营(T+3)**:打电话/上门后上传催款单截图 → `urge_records(urge_type='运营催款', urge_day=3)`。
- **销售(T+7)**:同上 → `urge_records(urge_type='销售催款', urge_day=7)`。
- **规则**:必须上传截图才能"标记已催"(运营/销售对客户面,截图为客户接触凭证,决策项 3)。
- **SLA**(决策项 20):
  - T+3 当日运营未催 → 次日通知运营主管。
  - T+7 当日销售未催 → 次日通知销售主管 + 老板看板红色徽标。

### H3 顺序扣款(T+7 仍未还,决策项 5、12、13)
- **抵冲资金池**:
  - 租赁:**押金**(`contracts.deposit_paid`,1~1.5 倍月租)。
  - 以租代售:**首付款**剩余可用部分(若约定预留缓冲)。
  - 客户预收(往期多打,详见 I2)。
- **优先级**(本次重定义,与 5.27 对齐):
  1. 保险/代办类(insurance_fee, service_fee)
  2. 维修/事故/罚金类(maintenance_fee, accident_fee, penalty_fee)
  3. 本期租金(rent)
  4. 滞纳金(late_fee,作为应收参与抵冲,优先级最低)
- **规则**:
  - 按上述顺序从资金池抵冲;每笔写 `reconciliation_allocations`。
  - **决策项 12**:滞纳金抵冲发生在 H3 中,**与 J3 减免审批相互独立**——
    - 已审批减免的部分:`late_fee_ledger.waived_amount` 累计,不参与抵冲。
    - 未减免部分:作为应收按优先级 4 抵冲。
  - **决策项 13(关键)**:**抵冲累计上限 = 押金/首付款余额**;一旦资金池清零仍有缺口,**停止累计、不再透支**,并把订单标记 `逾期-资金池耗尽`,推送销售/财务发"锁车提示"(决策项 21,不自动锁车)。
  - 同步更新 `contract_fee_items(fee_type='late_fee').amount_paid`。
- **输出**:扣款明细、剩余欠款、滞纳金累计/已抵冲/已减免。
- **界面要点**:运营/财务能看到"扣款瀑布"可视化;老板视图可穿透到任意一笔。

### H4 锁车提示(决策项 21)
- **触发**:H3 资金池耗尽 / 销售端"申请锁车"。
- **规则**:
  - **不自动远程锁车**,仅在销售工作台显示"建议锁车"红色徽标 + 锁车原因(欠款金额、逾期天数、资金池余额)。
  - 销售人工沟通后决定是否走线下锁车;如发起 `lock_requests`,需老板审批。
  - 前置校验:对应期数已存在 H2 催款记录。
- **输出**:`lock_requests(status='待审批')`,推送老板。

## 模块 I — 还款确认与计划表调整

### I1 运营登记本期还款(v2 修订,决策项 7)
- **触发**:客户支付后,运营点【本期还款】。
- **输入**:
  - **必填**:期数、实收金额、**客户付款截图**(运营对客户面,截图必填)。
  - **多还场景必填**:抵扣月份选择(运营与客户当面/电话确认,前端弹框记录确认时间)。

  - 写 `repayments.paid_amount`、`screenshot_path`,状态置 `部分核销`(待财务核对)。
  - **决策项 7**:**多还抵扣月份的客户确认在 I1 阶段完成,运营负责留痕**;前端弹框需勾选"已与客户确认抵扣月份",写 `repayments.extra_alloc_confirmed_by/at` 与 `repayments.extra_alloc_periods`。
  - 缺少客户截图 → 前端禁用提交。

### I2 财务核销(决策项 7、15)
- **触发**:I1 上传后,财务点【核销确认】。
- **输入**:
  - **必填**:银行流水号、实际到账金额。
  - **选填**:公司收款截图。
- **规则**(三分支):
  1. **等额**(`received == amount`):`status='已还款'`,计划表不变。
  2. **少还**(`received < amount`):
     - 当期 `paid_amount=received`,`status='部分核销'`。
     - 差额 `gap = amount - received` 累加到下一期 `repayments[period+1].amount += gap`。
     - 若已是末期则进入 H3 顺序扣款 / 退车结算。
     - **决策项 13**:差额累计上限 = 押金/首付款抵冲能力,资金池耗尽后停止累计。
  3. **多还**(`received > amount`):
     - 当期 `status='已还款'`。
     - 多余 `extra = received - amount`,**按 I1 已确认的抵扣月份**,系统把对应后续 N 期 `status='预抵'`、`paid_amount=amount`。
     - 抵不完的余额记为 `客户预收`(`customer_prepayments` 表),下次抵冲。
     - **决策项 7**:I2 阶段不再让财务"二次确认抵扣月份",避免责任错位。
- **输出**:`bank_serial`、`verified_amount`、`waterfall_summary` 全量写入。
- **决策项 15**:**财务责任口径 = 流水真实性、金额一致性**,**不再承担"是否抵扣哪几期"决策**(那是运营+客户共同确认的)。
- **审计**:每次核销均写 `reconciliation_allocations`。

### I3 计划表展示
- **界面要点**:
  - 展示客户表 + 厂家表两栏对照;
  - 已"预抵"期数加灰色徽标 + 抵扣来源期数提示;
  - 当期"差额顺延"用箭头连接后期。

## 模块 J — 滞纳金

### J1 计提规则(逾期即收,决策项 5)
- **触发**:H1 日终批处理(`due_date < today` 且当期未结清)。
- **公式**:
  ```
  outstanding(t) = amount - paid_amount(t)        # 原始未还本金,不扣押金抵冲
  daily_amount   = outstanding(t) × 0.0005        # 万分之5/日
  cumulative     = Σ daily_amount                 # 从首次逾期日起,无复利
  ```
- **决策项 5(关键)**:
  - 滞纳金计提基础**永远是当期原始 `amount - paid_amount`**,**不因 H3 押金抵冲而减少基数**。
  - **押金/首付款抵冲只发生在 T+7 节点的 H3 顺序扣款**,且抵冲后 `late_fee_ledger.outstanding_for_late_fee` 字段单独记录"用于计提的本金口径",与"应收口径"分离。
  - **不计复利**:滞纳金本身的逾期不再产生新的滞纳金。
- **写入**:`late_fee_ledger(repayment_id, accrued_date, outstanding, daily_amount, cumulative_amount)`,`UNIQUE(repayment_id, accrued_date)` 防重。
- **同步落账**:每日批处理同时写/更新 `contract_fee_items(fee_type='late_fee')`,`amount_due = cumulative` 并同步状态,使其进入正式应收口径。

### J2 抵冲与收取
- **逾期 = 应收**:滞纳金一旦计提即为客户应付债务,需要收取。
- **抵冲优先级**:在 H3 顺序扣款中,`late_fee` 排在第 4 位(本期租金之后);客户主动还款时,如本期款项有富余且没有更高优先级未结项,则抵冲已计提滞纳金。
- **结清前提**:合同结清(自然/提前/退车)前,若 `late_fee_ledger` 存在未抵冲累计金额,必须走 J3 减免审批,否则视为应收,并入退车押金扣除或提前结清买断金额。

### J3 减免审批(销售发起 → 老板审批 → 财务执行)
- **触发**:销售端"滞纳金减免申请"(可在还款过程中、退车节点、提前结清节点发起)。
- **输入**:合同 ID、命中期数(可多选/全选)、减免金额或全额减免、原因、附件(可选)。
- **数据表**(决策项 30,统一表名 `waivers`):
  ```sql
  -- 重命名 rent_waivers → waivers,新增字段
  ALTER TABLE rent_waivers RENAME TO waivers;
  ALTER TABLE waivers ADD COLUMN waiver_kind TEXT DEFAULT 'rent';   -- 'rent' | 'late_fee'
  ALTER TABLE waivers ADD COLUMN target_period_list TEXT;           -- JSON: [1,2,3] 或 'all'
  ```
- **流程**:
  1. **销售发起** → `waivers(waiver_kind='late_fee', status='待审批')`,推送老板待办。
  2. **老板审批** → 通过/驳回 + 备注;通过后 `status='已通过'`,推送财务待办。
  3. **财务执行**:
     - 在 `late_fee_ledger` 中按命中期数标 `waived=1`、`waived_amount=...`(新增字段)。
     - 同步 `contract_fee_items(fee_type='late_fee').amount_due -= waive_amount`。
     - 写 `reconciliation_allocations(allocation_type='late_fee_waiver', allocated_amount=waive_amount)`。
     - `waivers.status='已生效'`,`finance_reviewed_by/at` 落库。
- **决策项 12**:J3 与 H3 互斥处理——已减免部分不再参与 H3 抵冲;未减免部分按 H3 优先级 4 抵冲。
- **撤销规则**:仅"已通过未生效"可撤销;"已生效"需通过"反向减免登记"补登。
- **通知**:推送给销售、运营、客户对账页。

### J4 结算时机(v2 修订,决策项 2)
- **退车节点(M 模块)**:
  - 若存在未减免/未抵冲的 `late_fee` 累计金额,M3 运营查数据时自动汇总到 `total_deduction`。
  - 销售如需减免,**必须在 M1 之前或 M3 之前完成 J3 流程**,得到老板批复后方可在退车单中体现。
  - **决策项 2**:**不再由销售在退车单上单点决定**,`return_inspections.waive_late_fee` 字段仅用于展示是否已经走完 J3(只读标记位)。
- **以租代售结清/提前结清(N 模块)**:同上,需提前完成 J3 才能进入过户。

### J5 展示
- 合同详情页"滞纳金累计"卡片:本月新增 / 累计金额 / 起算日 / 已抵冲 / 已减免 / 待收。
- 老板穿透:可查任一车辆的滞纳金 ledger 与减免审批链路。

## 模块 L — 发票申请

- **触发**:财务待办"待开票"。
- **输入**:**发票号(必填,长度 ≥ 8,字母数字)**、开票时间(必填)、发票 PDF/截图(选填,决策项 3)。
- **规则**:`status='已开票'`,写 `invoiced_at`、`processed_by`。

### L3 发票纠错(作废 vs 红冲,决策项 29)
- **场景区分**:
  - **作废(本月内)**:发票尚在当月、且未跨账期 → 走"作废"动作,等价于"未开过"。
  - **红冲(跨月/已申报)**:发票已跨月或已纳入纳税申报 → 必须走"红冲发票"流程,不可直接作废。
- **触发**:财务在已开票记录上点"作废"或"红冲"按钮(系统按开票时间自动判断默认动作,允许财务覆盖)。
- **输入**:
  - 作废:作废原因(必填)、作废凭证(选填)。
  - 红冲:红冲原因(必填)、红冲蓝字凭证(必填,作为税务凭据)、红冲日期。
- **流程**:
  1. **作废**(适用本月内):`invoice_requests.status='已作废'`,记录 `voided_by/voided_at/void_reason`。系统保留原发票号、开票时间用于审计追溯,**不可删除**。
  2. **红冲**(适用跨月):`invoice_requests.status='已红冲'`,记录 `red_invoice_no`(红冲蓝字票号)、`red_invoiced_at`、`red_reason`、`red_certificate_path`(必传)。
  3. **重新上传(可选)**:作废/红冲后系统自动派生一条同合同同期数的新记录(`status='待重开'`,`previous_invoice_id` 指向被作废/红冲的记录),进入财务待办。
  4. **重开提交**:财务在重开记录上重新填写发票号(必填)、开票时间(必填)、发票 PDF/截图(选填),提交后 `status='已开票'`。
- **数据模型扩展**:
  ```sql
  ALTER TABLE invoice_requests ADD COLUMN voided_by TEXT;
  ALTER TABLE invoice_requests ADD COLUMN voided_at TEXT;
  ALTER TABLE invoice_requests ADD COLUMN void_reason TEXT;
  ALTER TABLE invoice_requests ADD COLUMN previous_invoice_id INTEGER;
  -- 红冲专用字段
  ALTER TABLE invoice_requests ADD COLUMN red_invoice_no TEXT;
  ALTER TABLE invoice_requests ADD COLUMN red_invoiced_at TEXT;
  ALTER TABLE invoice_requests ADD COLUMN red_reason TEXT;
  ALTER TABLE invoice_requests ADD COLUMN red_certificate_path TEXT;
  ```
- **可作废/红冲的状态**:仅 `已开票` 可作废/红冲;`待开票`、`已作废`、`已红冲` 不可再次操作。
- **审计**:作废、红冲、重开均写 `audit_logs`,操作人、时间、原因全量记录;客户对账页能看到完整版本链(蓝色发票 / 灰色作废 / 橙色红冲徽标)。

### L4 客户对账
- 合同详情"发票记录"卡片展示有效发票(`status='已开票'` 且未被作废/红冲)+ 历史版本链;运营可下载有效版本。

## 模块 M — 退车(到期 / 提前)

### M1 销售发起退车
- **触发**:销售端"发起退车"。
- **场景**:① 租期到期且末期已收;② 客户申请提前退车。
- **输入**:
  - 退车原因(到期退车/提前退车/租赁转购车/临时用车)、附件。
  - **决策项 16**:**提前退车违约金**输入字段(可选,有约定时由销售填写,展示给后续 M3 运营、M4 财务复核)。
  - **决策项 2**:**不再由销售在此勾选"是否减免滞纳金"**;若有减免需求,需提前完成 J3 减免审批,本节点仅展示"滞纳金累计 / 已减免"两个只读字段。
- **规则**:写 `return_inspections(sales_status='已登记')`,合同状态=`退车中`,车辆状态=`退车中`(决策项 24,新增显式状态)。

### M2 车管验车
- **触发**:车回库后车管端"验车"。
- **输入**:
  - 随车工具(三角架/反光衣/灭火器/楔块/千斤顶)、证件钥匙。
  - 公里数、车身/轮胎清洁、事故/违章/ETC/维修保养、出险加保费。
  - **附件**:验车现场照片(必填,与 G3 出库照片对比基线,决策项 35)。
  - 若需维修勾选"待维修"。
- **规则**:`fleet_status='已填写'`,无问题 → 待运营查数据;有维修 → **车辆状态置 `待维修`**(决策项 6,只有此处能进入 `待维修`)。

### M3 运营查数据并填单
- **触发**:M2 完成后。
- **输入**:违章/ETC/事故等明细、应扣金额、押金抵扣项;**滞纳金应收(只读,从 J1 ledger 自动汇总)**。
- **规则**:`operator_status='已填写'`,自动汇总 `total_deduction`、`actual_refund`。

### M4 财务复核押金(决策项 16)
- **触发**:M3 完成后。
- **规则**:
  - **到期退车**:`actual_refund = deposit_paid - total_deduction(含未减免滞纳金)`,`status='待退款'`。
  - **提前退车**:
    - 若 M1 填写了违约金 → 加入 `total_deduction`。
    - 若押金不够覆盖扣减 → 差额记 `accounts_receivable`,推送销售去追收。
  - `finance_status='已填写'` + `finance_approved=1`。

### M5 领导审批
- **触发**:M4 完成后,**领导审批 = 老板**(`approval_flows.ref_type='return_stock'`)。
- **规则**:通过=`boss_approved=1`,允许出款。

### M6 出款 + 入库
- **触发**:M5 通过。
- **规则**:财务出款打到客户账户,**必填银行流水号、扣减金额明细**(决策项 3,L-附);`paid_out=1`;车辆 `status='在库'`(若验车时为待维修则保持 `待维修`,修复后再回库)。
- **输出**:租赁流程结束,合同 `contract_status='已退车'`。

## 模块 N — 过户(以租代售结清 / 提前结清)

### N1 自然结清(决策项 18)
- **触发**:I 模块某一期核销后,系统检测 `Σ paid_amount ≥ Σ amount` 且 `period == loan_periods`。
- **幂等键**:`ownership_transfers` 表新增 `idempotency_key = sha256(contract_id + 'natural_settle')`,UNIQUE 约束;同一合同重复触发只生成一条过户单。
- **规则**:
  1. 财务复核结清,**前置**:必须先完成 J3(若有未减免滞纳金)。
  2. 创建 `ownership_transfers(status='待过户', idempotency_key=...)`,推送运营。

### N2 提前结清买断(决策项 19)
- **触发**:运营端"计算剩余应还本金"。
- **公式(展开版)**:
  ```
  remaining_principal = Σ_{未还期} amount             # 剩余应还本金
                     - 已审批减免金额                # 来自 K3/J3
                     + 未减免滞纳金累计              # 来自 J1 ledger
                     + 未付清应收(保险/维修/事故/罚金)# 来自 contract_fee_items 应收差
                     - 客户预收余额                  # 来自 customer_prepayments
  ```
- **流程**:
  1. 运营计算并出报价 → 与客户确认。
  2. 客户一次性支付 → 运营上传客户截图(必填) → 财务确认收款(必填银行流水号,选填公司截图) → 写 `contracts.early_settlement_amount/early_settled_at/early_settlement_serial`。
  3. 触发 N3 过户。
- **幂等**:与 N1 类似,`idempotency_key = sha256(contract_id + 'early_settle')`。

### N3 过户登记
- **触发**:N1 / N2 完成后。
- **输入**:过户日期、新车主名称、新车主身份证、过户材料附件(行驶证、登记证)。
- **规则**:
  - 写 `ownership_transfers(status='已过户', transfer_date)`。
  - 车辆 `status='已售/已过户'`,合同 `contract_status='已结清'` 或 `已提前结清`。
- **异常**:材料不全的过户单不能完结,可挂"待过户"长期跟踪。

## 模块 V — 非功能要求(幂等 / SLA / 时间口径,决策项 18、20、33、34)

### V1 幂等性(决策项 18、33)
- **核心写动作必须幂等**:
  - 报单提交:`sales_orders.idempotency_key = sha256(销售id + VIN + 起租日 + 提交时间戳分钟级)`。
  - 还款核销:`reconciliation_allocations.idempotency_key = sha256(repayment_id + bank_serial)`。
  - 自然结清/提前结清:见 N1/N2。
  - 发票开具:`invoice_requests.idempotency_key = sha256(contract_id + period + invoice_no)`。
  - 滞纳金计提:`late_fee_ledger UNIQUE(repayment_id, accrued_date)`(已有)。
- **重复请求**:返回原结果(HTTP 200 + `idempotent_replay=true` 标识),不报错。
- **异常恢复**:cron 任务允许重跑,内部按幂等键去重。

### V2 SLA 超时提醒(决策项 20)

| 节点 | 超时阈值 | 处理 |
|---|---|---|
| 老板价格特批(E1) | 24h | 系统每日给老板推提醒 + 销售可催办 |
| 财务报单确认(E2) | 24h(F3 完成后) | 推送财务主管 |
| 老板减免审批(K2/J3) | 48h | 销售催办 + 看板红色 |
| 财务减免执行(K3/J3) | 24h | 推送财务主管 |
| 老板退车审批(M5) | 48h | 销售/财务催办 + 看板红色 |
| 财务出款(M6) | 财务审批后 3 工作日 | 看板黄色 → 红色升级 |
| T+3 运营催款(H2) | 当日内 | 次日提醒运营主管 |
| T+7 销售催款(H2) | 当日内 | 次日提醒销售主管 + 老板看板 |
| 财务开票(L2) | 申请后 3 工作日 | 推送财务主管 |
| 过户登记(N3) | 结清后 30 日 | 推送运营主管 |

- **实现**:cron 每日扫描各业务表 `created_at / submitted_at`,落 `sla_alerts` 表 → 工作台徽标 + 站内信。

### V3 时间口径(决策项 34)
- **统一口径**:
  - "当月" = 自然月(本月 1 日 0 时 ~ 本月末日 23:59:59)。
  - "应还" = 以 `repayments.due_date` 为锚。
  - "实收" = 以财务核销时间 `verified_at` 为锚。
  - "逾期天数" = `today - due_date`(忽略时分,按整日)。
- **数据库时间字段**:统一存 ISO 8601 字符串(`YYYY-MM-DD HH:MM:SS`),入库前 trim,展示前按客户端时区(默认 +08:00)。
- **跨月切换**:每月 1 日 00:30 cron 重算"上月闭口数据"快照,写 `monthly_snapshots`,Q 看板的"上月对比"读快照。

### V4 缓存与性能
- 老板看板首屏 < 2s:聚合查询缓存 5 分钟,任何写入操作触发对应主键失效。
- 单车盈利计算异步化:E2 激活后入队,5 分钟内生成,失败重试 3 次后告警。

### V5 数据备份与审计
- 数据库每日 02:00 全量备份,保留 30 日。
- `audit_logs` 不可删除,仅可压缩归档(超过 1 年迁移至冷库)。
